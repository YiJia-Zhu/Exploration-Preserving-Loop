# 当前实验计划：先Ablation确定方案

2026-11-17补充：下一步正式baseline仅LoopOPD 4→2，与我们的gate＋JS固定4→2比较；见[正式协议](18_formal_experiment_plan.md)。下文A–H及其他深度用于独立消融和历史方案说明，不加入本轮正式baseline表。旧实验输出及checkpoint已按用户要求清理，当前GPU6、7运行保留。

主定义见[研究方案](loop_distillation_research_proposal_zh.md)。当前方案与全部对照都作为方法消融：先在开发集确定方法，再做参数实验，最后固定设置进行正式baseline比较。当前默认E；固定预算Top-S为F。两种模型分别比较，不混报参数规模、阈值或基准结果。具体阶段与命名见[实验流程](13_experiment_workflow.md)。

| 组别 | 设置 | 要区分的作用 |
|---|---|---|
| A | 原生动态基模，直接推理 | 未蒸馏的计算与精度 |
| B | 原始LoopOPD，固定学生轮数 | 终点蒸馏消融对照；本轮正式baseline仅4→2 |
| C | 动态学生，同样S_t标签，只在学生第S_t轮学教师终点 | 单纯动态分配与停止学习 |
| D | 动态学生，同样S_t标签，教师目标均匀分段 | 中间监督本身 |
| E | 动态学生，全部超阈值边界，真实JS段末与退出学习 | 主方法 |
| F | 固定预算S，最多Top-(S−1)边界，段末监督 | 旧固定预算方案 |

C/D/E均从同一JS规则生成S_t与停止标签。C只有一个KL项，不把它的KL项数误记为S_t；D/E按同一阶段数平均KL。各组学生训练后前缀不同，不强行复用跨组退出标签。

配置见[Ouro矩阵](../experiments/experiment_matrix.csv)与[Huginn矩阵](../experiments/huginn_experiment_matrix.csv)。C/D/E另有 `_current` 教师参数刷新版；先以冻结版与原始LoopOPD公平比较。教师参数动态与学生计算动态是不同变量。

## 参数与数据

Ouro B保留LoopOPD参考设置：K=4、S=2、DAPO 17,398题、32×8=256条回答／更新、100更新、AdamW LR1e-6、WD0.01，冻结教师无warmup。D-LoopOPD参数刷新对照warmup10。新方法继承这些优化／采样设置，仅修改阶段目标、停止损失与学生策略。

Huginn验证上限32、上下文4096，prompt上限1024、生成上限3072。这是同基模适配，不冒称LoopOPD或BoD的Huginn分数复现。JS阈值、β和学生停止阈值仅用训练开发数据选择，测试集不调参数。当前τ=0.05、β=1为开发起点。

源数据保留原消息、题目ID、内容哈希，训练/dev/test按题目去重。可选结果筛选由冻结教师原生动态作答一次；各组共享正确性接受池，只缓存接受标签，不复用离线退出深度。

## 必须观察什么

- 完整测试集准确率、生成长度、停止token与截断情况。
- 教师n_t、目标S_t、实际S_hat_t三套分布；实际平均轮数、分位数与达到K的比例。
- 退出预测绝对误差、目标／实际深度混淆矩阵、提前退出后训练补算量、S_t=n_t比例。
- 阶段KL、停止BCE、实际teacher/student前向token-loops、教师coda读出、耗时与显存。
- 精度—实测平均循环数、精度—实测耗时曲线，不由标签均值推断速度。

默认动态学生采用精确按需补齐的深度KV缓存，B保留原论文风格的固定深度缓存。动态学生需同时报告历史补算token-loops和coda开销，不能只用新token出口深度比较成本。`use_cache=false`与 `loopopd_recompute.json` / `huginn_loopopd_recompute.json` 保留为旧重算诊断，见[缓存说明](10_dynamic_kv_cache.md)。可运行`loopopd_s1/s3/s4.json`和`huginn_loopopd_s4/s16/s32.json`补充固定预算曲线。

原生Ouro A可能选浅出口但仍计算K轮。评测同时保存所选出口与真实执行深度，不把二者混为一项。查询冻结／恢复只作为后续独立机制检查。

## 当前方法消融：真实权重短训

先用Ouro-1.4B-Thinking进行20-update方法消融，默认运行E候选方法，可切换C/D监督、边界信号和教师筛题；A提供原生动态参考，B作为显式可选的LoopOPD消融对照。E每个token由自己的退出头选择实际轮数，`K=4`仅是最大上限；JS超阈值的边界全部保留，不预设二轮、不指定平均轮数，也不使用缓存测速脚本中的强制出口序列。只有B按原论文固定二轮学生、四轮教师。

消融起点使用冻结教师，seed42，训练256题、开发64题，全部64道DAPO留出题用于评测，与训练题目互斥；每次更新4题×4条回答=16，LR=1e-6，WD=0.01，BF16，prompt上限1024、训练与评测回答生成上限均为16,384 tokens，训练采样temperature=1/top_p=1。默认GPU为2、3。E的开发起点为JS阈值0.05 nats、stop BCE系数1、学生本地停止阈值0.5、教师CDF阈值0.9；训练前评测原生动态模型，第10和20次更新保存后动态评测。阈值尚未校准，开发集评测不用于正式结论。

首先核对教师终点`n_t`、阶段目标`S_t`、学生实际出口`S_hat_t`及其误差，再比较正确率、截断率、包含历史补算的真实token-loops、延迟和显存。若深度集中在1或K，检查是轨迹本身、阈值还是停止头造成；不人为制造混合深度。之后补C动态终点、D动态均匀阶段，区分JS选点、阶段监督与动态停止各自的作用。

启动入口改为`scripts/run_ablation.sh`，默认`METHOD=ours`，输出`experiments/ablations/`；不是参数扫描或正式baseline比较脚本。默认`EVAL_INITIAL_FIXED=0`，只运行原生动态初始参考；固定深度初始预算曲线需显式开启。E训练与评测都使用学习到的停止策略，主评测不传`--loops`。本轮使用固定revision的公开DAPO数据，17,398道去重题目排除7道答案冲突题后为17,391题；按seed42划分训练256题与开发评测64题，详细来源、配置及启动状态见[启动记录](../audit/dapo_launch_20261114/README.md)。公开数据处理与论文内部子集的一致性尚未独立确认。

## 追加消融：边界信号与回答正确性

同一方法消融阶段按[消融协议](12_confidence_and_correctness_ablations.md)独立比较：

- G：以最大概率变化、归一化熵变化、probe_know替代JS；保留动态学生、原生教师终点和阶段损失。先做少量前缀诊断，再决定探针全位置训练。
- H：教师正确题目池与不筛选题目；B/E共享相同池，另用random_matched控制保留数量。

默认仍为JS、不筛选、不强制深度。学生回答无论对错均参与蒸馏；不按学生回答正确性过滤。只筛训练集，不按开发／测试集答案过滤。报告筛选／探针总成本、保留题目数量、训练更新数、正确率与实际计算；不能把自报信心当作正确性验证器。附加配置见[消融矩阵](../experiments/ablation_matrix.csv)。
