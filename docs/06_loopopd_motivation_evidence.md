# LoopOPD改进的动机与证据边界

当前主路线见[动态学生研究方案](loop_distillation_research_proposal_zh.md)。

LoopOPD提供密集的token终点分布监督，梯度也经过循环内部。我们的假设是：在计算受限时，阶段末轮可能比单一深轮终点更容易承接；同时，不同token需要的阶段数不同，可以学习动态停止。不能仅因原目标没有中间项，就断言它压坏了必要探索。

如果学生在所有可达前缀上精确匹配教师终点条件分布，序列分布也会一致。因此研究焦点是有限预算、优化难度和实际计算分配。

[Query Handoff](../ref/2610.34639v1_query_handoff.pdf)在限定两跳任务里通过查询冻结与移植说明部分更新有任务作用；[Compute/Retain/Reuse](../papers/2610.19768v1_compute_retain_reuse.pdf)提醒可读答案与可继续使用的状态不同。它们没有验证JS边界、阶段数标签或本方案退出头。

本项目[历史干预](07_pilot_results_20261108.md)也只提供局部功能证据。当前E需要C/D/E的同标签对照、B/F的计算曲线和独立任务结果，再考虑用冻结／恢复检验所选阶段。高JS、阶段KL下降或退出预测准确，单独都不足以证明必要探索被保留。

工程实现当前已区分教师n_t、目标S_t与实际S_hat_t；逐轮停止和前缀补算都计入执行成本。验证入口见[实现说明](08_implementation_and_reproduction.md)。
