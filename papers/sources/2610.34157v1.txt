Abstract
Generative recommendation formulates item recommendation as autoregressive generation rather than a discriminative scoring problem. Although empirical studies exhibit favorable scaling behavior in recommendation, unleashing the benefits of scaling remains challenging under the strict model size and inference cost constraints of real-world systems. A central challenge is to combine expressive modeling of user-item interaction histories with flexible computational depth without proportionally increasing model size.
We introduce LoopGR, a parameter-efficient scaling framework for generative recommendation via recurrent depth. LoopGR employs a tailored hierarchical recurrent depth mechanism that alternates between a shared generative decoder and a lightweight context updater. For efficient inference, we further develop recurrent trajectory self-distillation that distills a low-budget student from a high-budget teacher by aligning both predictive distributions and evolution directions.
Extensive experiments show that LoopGR consistently outperforms strong generative recommendation baselines. Compared with a representative encoder–decoder baseline, LoopGR achieves superior performance while reducing model size by up to 52%. These results establish recurrent depth as a new scaling dimension, offering a flexible and resource-efficient scaling path for generative recommendation.

1 Introduction
Generative recommendation, which reconceptualizes the traditional discriminative matching paradigm as a generative task, has been a promising paradigm for large-scale recommender systems (Wang et al., 2023; Zhou et al., 2025a; Cheng et al., 2026). Inspired by tokenization in LLMs and computer vision, recent methods represent each item as a short sequence of discrete semantic IDs (SIDs) and formulate next-item recommendation as autoregressive generation of the target SIDs (Rajput et al., 2023; Ju et al., 2026; He et al., 2026). Empirical studies further suggest that increasing model capacity and training computation can improve recommendation performance, suggesting that generative recommenders also benefit from predictable scaling laws (Guo et al., 2024; Liu et al., 2026; Hou et al., 2026). However, unlike LLMs, recommender systems are deployed under much tighter computational and serving constraints. The key challenge is not simply to increase computation, but to effectively allocate a limited computational budget between interaction history modeling and target SID generation.
Existing generative recommenders allocate computation differently between history modeling and target generation, as illustrated in Figure 1. This architectural evolution progressively shifts computation from dedicated history modeling toward shared and ultimately target-centric computation (Rajput et al., 2023; Zhou et al., 2025b; Yang et al., 2025b).
The above architectural designs reveal a common conflict between expressive context modeling and efficient target generation. Rich user-item context is typically obtained by deeply encoding historical interactions before generation, whereas efficient decoding often treats the resulting context as fixed conditioning. Meanwhile, computational depth remains tightly coupled with the number of network layers in existing architectures, such that deeper context refinement requires additional parameters.
These observations motivate a central question:
How can we design a flexible generative recommendation backbone that dynamically organizes computation between context modeling and target SID generation?
Looped Transformers, which recursively apply a set of shared layers across recurrent steps, offer a promising way to decouple computational depth from parameter size or memory consumption (Yang et al., 2025a; Zhu et al., 2025b; Geiping et al., 2026). Early studies combined recurrent depth with adaptive computation to iteratively refine token representations (Dehghani et al., 2018; Graves, 2016), while recent work has revisited this paradigm to improve the reasoning and efficiency capabilities in modern language models (Prairie et al., 2026; Wang et al., 2025a; Saunshi et al., 2025).
Although recurrent depth improves model efficiency via parameter sharing, it is hard to differentiate two distinct computations over long behavioral histories and target SIDs in generative recommenders. Moreover, additional recurrent steps still incur inference latency, making unrestricted looping impractical under strict serving budgets. This motivates a recommendation-specific recurrent design that separately organizes history refinement and target generation while supporting efficient low-budget inference.
Figure 1: Backbone comparison of different generative recommendation frameworks. (a) Encoder-Decoder architectures allocate separate computation to history modeling and target generation. (b) Decoder-Only architectures unify this computation within a shared stack. (c) Lazy Decoder-Only architectures further reallocate the computational budget toward target generation.
In this paper, we propose LoopGR, a parameter-efficient scaling framework for generative recommendation via hierarchical recurrent depth. LoopGR is part of the TGR series of generative recommendation research at Tencent Cheng et al. (2026).
It comprises an encoder, a shared decoder and a lightweight shared context updater. After the encoder initializes the behavioral context, high-level decoder cycles and low-level updater cycles are recurrently interleaved.
Specifically, the decoder predicts target SID representations from the current context while the updater feeds the emerging target state back to refine the context for subsequent decoding. This design allows user context to evolve during generation while scaling computational depth through shared layers. To support efficient inference under hard serving budgets, we propose a recurrent trajectory self-distillation to match predictive distributions and evolution directions from high-budget to low-budget recurrent trajectories.
LoopGR reconciles dynamic context modeling with efficient target generation by decoupling computational depth from parameter count while retaining strong performance under limited recurrent budgets.
Our contributions are summarized as follows:
• 
To the best of our knowledge, we are the first to introduce a recurrent-depth architecture for SID-based generative recommendation, which enables dynamic context refinement during target SID generation while decoupling computational depth from parameter count.
• 
We propose a recurrent trajectory self-distillation method that aligns both predictive distributions and their evolution directions. It avoids the entanglement between exit selection and trajectory formation and effectively transfers a high-budget teacher into a low-budget student for efficient inference.
• 
Extensive experiments show that LoopGR outperforms strong baselines with fewer parameters. Beyond overall comparisons, we systematically evaluate recurrent depth, model size and computation scaling. Trajectory-level analyses are conducted to characterize the evolution of predictive representations across recurrent steps.
2 Related Works
Generative Recommendation.
Generative recommendation has emerged as a new paradigm that directly generates target items from user-item interaction history (Hou et al., 2026; Li et al., 2025; Wang et al., 2026). With the rise of Large Language Models (LLMs), one line of studies adapts pretrained LLMs to recommendation by aligning their rich linguistic priors with recommendation-specific objectives (Zheng et al., 2024; Team et al., 2026; Zhang et al., 2026). For example, OneRec-Think (Liu et al., 2025) introduces itemic alignment, reasoning activation and reasoning enhancement to further equip recommenders with both explicit reasoning capabilities and personalized recommendation.
A complementary line forgoes linguistic priors in LLMs and trains a recommendation-tailored architecture from scratch (Rajput et al., 2023; Wang et al., 2025b; Wang et al., 2024). OneRec-V2 (Zhou et al., 2025b) proposes a lazy decoder-only architecture to reallocate computation toward the target SID generation and avoid repeatedly applying expensive sequence encoding. Besides, several studies have further explored latent reasoning for generative recommendation by introducing intermediate latent states (Yang et al., 2026; Chen et al., 2026; Tang et al., 2026a).
Despite these advances, most existing methods retain fixed-depth Transformer backbones, where increasing representational capacity typically entails introducing additional layers and parameters. Such parameter-centric scaling is difficult to reconcile with the stringent memory and latency requirements of recommendation systems.
Looped Transformers.
Looped Transformers increase effective computational depth by repeatedly applying a set of shared layers to decouple the computational depth from model size (Bai et al., 2019; Lan et al., 2019).
As an earlier study, Universal Transformers (Dehghani et al., 2018) proposes a self-attentive recurrent sequence model with Adaptive Computation Time (ACT) (Graves, 2016) to iteratively refine the symbol representations.
More recently, recurrent depth has been revisited in LLMs to improve parameter-efficient scaling and reasoning (Yang et al., 2024; Giannou et al., 2023; Fan et al., 2025). As an exemplary implementation, Ouro (Zhu et al., 2025b) repeatedly reuses a Transformer stack and systematically studies the scaling behavior of looped language models. Huginn (Geiping et al., 2026) adopts a different architecture in which the iterative body is tied between prelude and coda stacks.
In recommender systems, recurrent depth remains largely underexplored. LoopCTR (Tang et al., 2026b) uses a parameter-shared prefix-attention module as the recurrent block for CTR prediction. However, it tailors recurrence layers to discriminative CTR prediction rather than autoregressive item generation. Deeper recurrence introduces additional sequential computation, making the balance between recurrent depth and inference efficiency an important direction for recommender systems.
3 Preliminaries
Semantic ID-based Generative Recommendation.
Let ℐ={1,…,N}\mathcal{I}=\{1,\ldots,N\} denote the item set and 𝒮u=(i1,…,in)\mathcal{S}_{u}=(i_{1},\ldots,i_{n}) the user-item interaction history of user uu. The goal of next-item recommendation is to predict the subsequent item in+1∈ℐi_{n+1}\in\mathcal{I}.
Instead of assigning each item an atomic identifier, semantic ID-based generative recommendation represents an item ii by a hierarchical code sequence 𝐜i=(ci1,…,ciH)\mathbf{c}_{i}=(c_{i}^{1},\ldots,c_{i}^{H}), where HH is the length of SIDs and cihc_{i}^{h} denotes its code at hierarchy hh. Following prior work (Lee et al., 2022), each SID consists of semantic tokens generated by a Residual-Quantized Variational AutoEncoder (RQ-VAE) and an extra anti-collision token. Accordingly, next-item prediction over semantic IDs can be formulated as follows:
pθ​(in+1∣𝒮u)≡pθ​(𝐜in+1∣𝒮u)=∏h=1Hpθ​(cin+1h∣𝐜in+1<h,𝒮u),p_{\theta}(i_{n+1}\mid\mathcal{S}_{u})\equiv p_{\theta}(\mathbf{c}_{i_{n+1}}\mid\mathcal{S}_{u})=\prod_{h=1}^{H}p_{\theta}\!\left(c_{i_{n+1}}^{h}\mid\mathbf{c}_{i_{n+1}}^{<h},\mathcal{S}_{u}\right),
(1)
where θ\theta denotes the parameters of the generative recommendation model.
Recurrent Depth.
Looped architectures increase computational depth by repeatedly applying parameter-shared transformations. Given an initial hidden representation 𝐇(0)\mathbf{H}^{(0)}, the iterative computation can be written as
𝐇(t+1)=ℱϕ(𝐇(t);𝐄),t=0,…,T−1,\mathbf{H}^{(t+1)}=\mathcal{F}_{\phi}\!\left(\mathbf{H}^{(t)};\mathbf{E}\right),\qquad t=0,\ldots,T-1,
(2)
where 𝐄\mathbf{E} denotes the conditioning context. ℱ​ϕ\mathcal{F}{\phi} denotes a recurrent transformation whose parameters ϕ\phi are shared across iterations. TT denotes the number of recurrent steps, referred to as the loop budget. The intermediate states naturally form a trajectory in the latent space τ=(𝐇(1),𝐇(2),…,𝐇(T))\mathbf{\tau}=\left(\mathbf{H}^{(1)},\mathbf{H}^{(2)},\ldots,\mathbf{H}^{(T)}\right).
4 Methodology
Figure 2: Overview of LoopGR. LoopGR alternates a shared decoder with a shared context updater to jointly refine target SID predictions and context representations over hierarchical recurrent depth.
In this section, we formally define LoopGR from two complementary perspectives, architectural design and training objective. As illustrated in Figure 2, LoopGR encodes the historical interactions into a contextual memory and then alternates parameter-shared decoding and lightweight context updates to progressively predict the target SID along recurrent depth. This recurrent computation naturally forms a multi-step prediction trajectory, which we further exploit through a tailored training objective that first optimizes a high-budget teacher and then distills its trajectory into a low-budget student. Consequently, LoopGR defines how a trajectory is formed, while the objective determines how this trajectory is exploited under different inference budgets for generative recommendation.
4.1 LoopGR Architecture
Overall Design.
LoopGR organizes target generation as a hierarchical recurrent process consisting of an Encoder, a Context Updater and a Decoder. The hierarchical recurrent computation can be summarized as
ℱ=DEC∘ℬ∘⋯∘ℬ⏟high-level cycles∘ENC,ℬ≔UPD∘⋯∘UPD⏟low-level cycles∘DEC.\displaystyle\mathcal{F}=\operatorname{DEC}\circ\underbrace{\mathcal{B}\circ\cdots\circ\mathcal{B}}_{\text{high-level cycles}}\circ\operatorname{ENC},\qquad\mathcal{B}\coloneqq\underbrace{\operatorname{UPD}\circ\cdots\circ\operatorname{UPD}}_{\text{low-level cycles}}\circ\operatorname{DEC}.
(3)
where ∘\circ denotes function composition. The high-level recurrence repeatedly revisits target prediction, while each high-level transition contains a nested low-level recurrence for progressively refining its conditioning context.
Encoder.
We represent each historical item by its SIDs and obtain the corresponding token sequence 𝒞u=(𝐜i1,…,𝐜in)\mathcal{C}_{u}=(\mathbf{c}_{i_{1}},\ldots,\mathbf{c}_{i_{n}}). After embedding these tokens into 𝐗u∈ℝLu×d\mathbf{X}_{u}\in\mathbb{R}^{L_{u}\times d}, a Transformer encoder constructs the initial contextual memory:
𝐌(0)=ENC⁡(𝐗u),\mathbf{M}^{(0)}=\operatorname{ENC}\left(\mathbf{X}_{u}\right),
(4)
where LuL_{u} denotes the length of the historical SID token sequence and dd is the hidden dimension.
Context Updater.
The context updater is introduced between decoding cycles to progressively refine historical representations via the previous prediction state. Specifically, at the tHt_{H}-th high-level cycle and the tLt_{L}-th low-level cycle, the updater constructs a cycle-dependent condition and extracts a prediction-aware query from the intermediate hidden states produced by the Decoder as follows:
𝐞(tH,tL)=MLP(Emb(tH,tL,𝝃)),𝐪(tH)=MLP(𝐳BOS(tH)),\displaystyle\mathbf{e}^{(t_{H},t_{L})}=\operatorname{MLP}\left(\operatorname{Emb}(t_{H},t_{L},\bm{\xi})\right),\qquad\mathbf{q}^{(t_{H})}=\operatorname{MLP}\left(\mathbf{z}_{\mathrm{BOS}}^{(t_{H})}\right),
(5)
where 𝐳BOS(tH)\mathbf{z}_{\mathrm{BOS}}^{(t_{H})} denotes the hidden state of the BOS token after the tHt_{H}-th decoding cycle. As shown in Figure 2, the initial hidden states 𝐙(0)\mathbf{Z}^{(0)} are obtained by passing the context embeddings 𝐌(0)\mathbf{M}^{(0)} through the Decoder before the first context update. 𝝃\bm{\xi} denotes the hierarchy of SID.
These signals are injected into the context from the previous low-level step, and a lightweight sequence operator further refines the resulting conditioned representation:
𝐌~(tH,tL+1)\displaystyle\widetilde{\mathbf{M}}^{(t_{H},t_{L}+1)}
=UPD⁡(𝐌(tH,tL),𝐞(tH,tL),𝐪(tH)),\displaystyle=\operatorname{UPD}\left(\mathbf{M}^{(t_{H},t_{L})},\mathbf{e}^{(t_{H},t_{L})},\mathbf{q}^{(t_{H})}\right),
(6)
𝐌(tH,tL+1)\displaystyle\mathbf{M}^{(t_{H},t_{L}+1)}
=Norm⁡(𝐌(0)+𝐌~(tH,tL+1)),\displaystyle=\operatorname{Norm}\left(\mathbf{M}^{(0)}+\widetilde{\mathbf{M}}^{(t_{H},t_{L}+1)}\right),
(7)
In our implementation, the updater UPD⁡(⋅)\operatorname{UPD}(\cdot) shares parameters across all low-level cycles and is instantiated by default as a lightweight GRU-based operator. Notably, the updater is model-agnostic and we compare different instantiations in Section 5.5.
Besides, the initial context embedding 𝐌(0)\mathbf{M}^{(0)} provides a stable anchor for recurrent refinement to facilitate optimization over multiple low-level cycles. After TLT_{L} low-level cycles, the context embedding is passed to the Decoder in the next high-level cycle and serves as the initial context for subsequent refinement:
𝐌(tH+1,0)=𝐌(tH,TL)=Norm⁡(𝐌(0)+𝐌~(tH,TL)),\mathbf{M}^{(t_{H}+1,0)}=\mathbf{M}^{(t_{H},T_{L})}=\operatorname{Norm}\left(\mathbf{M}^{(0)}+\widetilde{\mathbf{M}}^{(t_{H},T_{L})}\right),
(8)
Decoder.
The decoder generates recurrent target SID representations from the current historical context. At each autoregressive generation step, the same decoding procedure is repeated for THT_{H} high-level cycles before the resulting prediction is used for subsequent generation. Each decoding cycle is explicitly:
𝐙^(tH)\displaystyle\widehat{\mathbf{Z}}^{(t_{H})}
=Norm⁡(𝐙(tH)+𝐞(tH)),\displaystyle=\operatorname{Norm}\left(\mathbf{Z}^{(t_{H})}+\mathbf{e}^{(t_{H})}\right),
(9)
𝐙(tH+1)\displaystyle\mathbf{Z}^{(t_{H}+1)}
=DEC⁡(𝐙^(tH),𝐌(tH+1,0)),\displaystyle=\operatorname{DEC}\left(\widehat{\mathbf{Z}}^{(t_{H})},\mathbf{M}^{(t_{H}+1,0)}\right),
(10)
where 𝐙\mathbf{Z} denotes the decoder input formed by the BOS token and the target prefix. Similarly, 𝐞(tH)\mathbf{e}^{(t_{H})} is constructed using the conditioning mechanism introduced above with tHt_{H} as the only cycle index. 𝐌(tH,0)\mathbf{M}^{(t_{H},0)} denotes the contextual memory used at the tHt_{H}-th high-level cycle.
4.2 Recurrent Trajectory Self-Distillation
Increasing recurrent depth allows LoopGR to refine its predictions without increasing the parameter count, but deeper unrolling inevitably introduces additional sequential inference cost. Therefore, we propose recurrent trajectory self-distillation to transfer the refinement dynamics of a high-budget LoopGR to a low-budget counterpart.
Let THt​rT^{tr}_{H} and THs​t​uT^{stu}_{H} denote the numbers of high-level cycles used by the teacher and student, where THs​t​u<THt​rT^{stu}_{H}<T^{tr}_{H}. We first train a high-budget teacher via the last step supervision.
We initialize the student from the trained teacher, θS(0)←θT⋆\theta_{S}^{(0)}\leftarrow\theta_{T}^{\star}, and reduce the recurrent budget to THs​t​uT^{stu}_{H} cycles. The above training objective can be formulated as follows:
θT⋆=arg⁡minθT⁡ℒtaskT⏟Stage I,θS⋆=arg⁡minθS⁡(ℒtaskS+α​ℒTraj+β​ℒDer)⏟Stage II,\displaystyle\underbrace{\theta_{T}^{\star}=\arg\min_{\theta_{T}}\mathcal{L}_{\mathrm{task}}^{T}}_{\text{Stage I}},\qquad\underbrace{\theta_{S}^{\star}=\arg\min_{\theta_{S}}\left(\mathcal{L}_{\mathrm{task}}^{S}+\alpha\mathcal{L}_{\mathrm{Traj}}+\beta\mathcal{L}_{\mathrm{Der}}\right)}_{\text{Stage II}},
(11)
where ℒtask\mathcal{L}_{\mathrm{task}} denotes the next-token prediction loss, and α\alpha and β\beta are loss weights. At each high-level cycle, the decoder hidden states are projected to token logits and converted into predictive distributions 𝐩\mathbf{p} via softmax. We align the student’s predictive distributions with those at the corresponding cycles along the high-budget teacher trajectory as follows:
ℒTraj=1THstu​H∑s=1THstu∑h=1H𝒟KL(𝐩tr(a⁡(s),h)∥𝐩stu(s,h)).\mathcal{L}_{\mathrm{Traj}}=\frac{1}{T_{H}^{\mathrm{stu}}H}\sum_{s=1}^{T_{H}^{\mathrm{stu}}}\sum_{h=1}^{H}\mathcal{D}_{\mathrm{KL}}\left(\mathbf{p}_{\mathrm{tr}}^{(a(s),h)}\,\|\,\mathbf{p}_{\mathrm{stu}}^{(s,h)}\right).
(12)
where a⁡(s)=⌈s​THt​rTHs​t​u⌉a(s)=\left\lceil\frac{sT^{tr}_{H}}{T^{stu}_{H}}\right\rceil. It maps each student cycle to the corresponding state along the teacher trajectory. Following prior trajectory distillation (Gong et al., 2025), we further minimize the directional discrepancy based on the first-order change:
ℒDer=1(THstu−1)​H​∑s=2THstu∑h=1H𝒟cos​(Δ​𝐳tr(a⁡(s),h),Δ​𝐳stu(s,h)),\mathcal{L}_{\mathrm{Der}}=\frac{1}{(T_{H}^{\mathrm{stu}}-1)H}\sum_{s=2}^{T_{H}^{\mathrm{stu}}}\sum_{h=1}^{H}\mathcal{D}_{\mathrm{cos}}\left(\Delta\mathbf{z}_{\mathrm{tr}}^{(a(s),h)},\Delta\mathbf{z}_{\mathrm{stu}}^{(s,h)}\right),
(13)
The finite differences in log-probability space are defined as Δ​𝐳S(s,h)=log⁡𝐩S(s,h)−log⁡𝐩S(s−1,h)\Delta\mathbf{z}_{S}^{(s,h)}=\log\mathbf{p}_{S}^{(s,h)}-\log\mathbf{p}_{S}^{(s-1,h)} and Δ​𝐳T(a⁡(s),h)=log⁡𝐩T(a⁡(s),h)−log⁡𝐩T(a⁡(s−1),h)\Delta\mathbf{z}_{T}^{(a(s),h)}=\log\mathbf{p}_{T}^{(a(s),h)}-\log\mathbf{p}_{T}^{(a(s-1),h)}.
Consequently, the student learns to approximate the high-budget refinement process with substantially fewer loop steps.
5 Experiments
5.1 Experimental Setup
Datasets.
We conduct experiments on three widely used categories from the Amazon Reviews 2014 dataset (McAuley et al., 2015): Sports and Outdoors (Sports), Beauty (Beauty) and CDs and Vinyl (CDs). We treat user reviews as implicit interactions and sort them chronologically to construct user behavior sequences. For the training set, we construct next-item prediction instances using sliding windows over each user’s interaction history (Rajput et al., 2023). We also evaluate LoopGR on an industrial dataset collected from Tencent’s production recommendation system and compare it with two generative recommendation baselines deployed in Tencent’s real-world services. More details about the datasets are provided in Appendix A.1.
Baselines.
We compare LoopGR with representative recommendation methods from two categories. (i) Conventional recommendation methods include GRU4Rec (Hidasi et al., 2015), SASRec (Kang and McAuley, 2018), BERT4Rec (Sun et al., 2019), FDSA (Zhang et al., 2019), S3-Rec (Zhou et al., 2020) and VQ-Rec (Hou et al., 2023).
(ii) Generative recommendation methods include TIGER (Rajput et al., 2023), HSTU (Zhai et al., 2024), ActionPiece (Hou et al., 2025b) and RPG (Hou et al., 2025a).
We report the best-performing full-budget LoopGR, together with LoopGR-RTSD, its corresponding student operating at half of the recurrent budget.
For the industrial dataset, we compare LoopGR with TIGER, BARGE (Zeng et al., 2026) and a plain Lazy Decoder-Only model derived from OneRec V2 (Zhou et al., 2025b). Notably, the encoder or context processor of each baseline is adapted to accommodate the industrial input format in our implementation.
Implementation Details.
All experiments are conducted on four NVIDIA H20 GPUs. For SID construction, we generate the semantic embedding of items using a pre-trained Sentence-T5 model (Ni et al., 2022) and quantize the resulting item embeddings with an RQ-VAE (Lee et al., 2022). The RQ-VAE produces a three-digit hierarchical SID for each item. Besides, we append a fourth anti-collision digit to ensure that every item has a unique SID.
For the LoopGR backbone, we instantiate the Encoder with T5 Encoder (Raffel et al., 2020) and employ a plain Transformer decoder (Vaswani et al., 2017) as the parameter-shared Decoder.

5.2 Overall Performance
Table 1 compares LoopGR with conventional sequential recommenders and recent generative recommendation methods. Overall, generative approaches achieve stronger performance across the three datasets, though several conventional methods remain competitive on individual metrics.
Generative methods exhibit stronger and more consistent performance, demonstrating the benefit of directly generating compositional item identifiers. LoopGR and LoopGR (RTSD) achieve the best result on 8 of the 12 evaluation settings. In particular, LoopGR improves over the strongest baseline by 2.4%2.4\% in Recall@5 and 2.1%2.1\% in NDCG@5 for Beauty, and by 5.4%5.4\% in Recall@5 and 4.2%4.2\% in NDCG@10 for Sports and Outdoors.
For generative baselines, ActionPiece and RPG employ more elaborate identifier or decoding designs. ActionPiece constructs context-dependent action tokens, whereas RPG adopts long unordered SIDs together with parallel prediction and graph-constrained decoding.
In contrast, LoopGR adopts a standard SID construction using RQ-VAE, while improving model capacity through a tailored hierarchical recurrent depth for generative recommendation. LoopGR outperforms RPG on 11 of 12 metrics and ActionPiece on 8 of 12 metrics. Moreover, LoopGR (RTSD) remains competitive while using fewer refinement steps and obtains the best Recall@10 on Beauty. It validates the effectiveness of trajectory self-distillation in iterative reasoning for a lower-computation model.

5.3 Architecture Comparison
To further investigate model size and recurrent-depth scaling, we compare LoopGR with three representative generative backbones, including Encoder-Decoder, Decoder-only and Lazy Decoder-only baselines. For parameter scaling, we fix TH=3T_{H}=3 and TL=1T_{L}=1 to compare LoopGR with the baselines at comparable parameter counts. For computation scaling, we search over encoder/decoder depths and TH/TLT_{H}/T_{L} to report the best configuration at comparable GFLOPs. Lazy Decoder-only is excluded from computation scaling because its computation is substantially lower than that of the other architectures. For hierarchical recurrence analysis, we fix both encoder and decoder to one layer and vary THT_{H} and TLT_{L}. More details about the inference latency are provided in Appendix A.2.
Parameter Scaling.
As shown in Figure 3 (a), LoopGR achieves higher NDCG@5 than the alternative architectures at similar parameter counts. Its performance continues to improve as the model size increases, while recurrent computation provides an additional dimension for increasing effective depth without introducing new parameters at every step. Consequently, its performance continues to improve beyond Encoder-Decoder as the parameter budget increases. In contrast, Lazy Decoder-only exhibits a flatter scaling curve because the historical context remains fixed and additional parameters are devoted primarily to target decoding.
These results suggest that hierarchical recurrence provides a more parameter-efficient scaling strategy for SID-based generative recommendation.
Computation Scaling.
LoopGR achieves the highest NDCG@5 across the different computation levels while requiring substantially fewer parameters than Encoder-Decoder. At approximately 0.50.5 GFLOPs, LoopGR uses only 1.31.3M parameters, less than half of the 2.72.7M parameters required by Encoder-Decoder.
Notably, with a parameter budget close to Decoder-only, LoopGR still outperforms the considerably larger Encoder-Decoder model. This demonstrates that additional computation can be introduced through parameter reuse rather than proportional model expansion, yielding a more favorable trade-off among accuracy, computation and model size.
Effect of Hierarchical Recurrent Depth.
We further vary the high-level depth THT_{H} and low-level depth TLT_{L} to examine their respective roles. Figure 3 (b) shows that removing low-level recurrence TL=0T_{L}=0 significantly degrades performance, while introducing even a small number of updater cycles improves both Recall@5 and NDCG@5. It highlights the importance of dynamically refining the historical context between successive decoding cycles.
Increasing THT_{H} generally brings further gains, although the gains become non-monotonic at larger depths. On Sports, increasing both THT_{H} and TLT_{L} yields more pronounced performance gains. This indicates that deeper hierarchical recurrence becomes increasingly beneficial as the recommendation scale grows.
Overall, these results support the hierarchical design of LoopGR, where high-level cycles progressively refine target prediction while low-level cycles adapt the conditioning context between decoding stages.
5.4 Analysis of Loop Dynamics
In this section, we visualize intermediate representation trajectories in latent space across recurrent steps. We focus on two questions: (Q1) how do the latent dynamics of LoopGR differ from those of a conventional Encoder-Decoder? and (Q2) how does trajectory distillation reshape these dynamics under a limited loop budget?
We collect the intermediate representations at different SID positions from a 16-layer Encoder-Decoder, a 16-loop LoopGR teacher and distilled students with 8 and 4 loops. For each SID position, we project the intermediate states onto the first two principal components to trace their evolution. Figure 4 provides a visualization of these trajectories.
Figure 4: Latent space trajectories for different SIDs.
Q1: How do the latent dynamics of LoopGR differ from a conventional counterpart?
As depicted in Figure 4, the Encoder-Decoder exhibits relatively smooth layer-wise evolution. Its adjacent representations progressively move along a largely continuous trajectory. In contrast, LoopGR undergoes substantially larger transitions in its early cycles and subsequently enters a more localized refinement regime.
In the experiments, LoopGR exhibits clear position-dependent dynamics that are characterized by stronger oscillations at earlier SID positions and faster convergence at later SID positions.
These non-monotonic patterns resemble the structured latent trajectories observed in previous Looped Transformers (Geiping et al., 2026; Wang et al., 2025a). Unlike the progressive layer-wise transformations of the Encoder-Decoder, LoopGR repeatedly revises its latent state across cycles, yielding a more dynamic and position-dependent refinement process.
Q2: What does trajectory distillation learn?
Figure 4 shows that reducing the loop budget through distillation does not simply truncate the teacher trajectory. The 8-loop student exhibits a much larger transition at the beginning of recurrent computation, followed by progressively smaller updates toward its terminal state. This tendency becomes even more pronounced for the 4-loop student, whose trajectory is dominated by the initial transition.
Here, we propose an intuitive interpretation that the distillation objective encourages a low-budget model to approximate a longer refinement process with fewer recurrent transitions rather than reproducing every intermediate teacher state. Consequently, the teacher and student exhibit complementary computational behaviors. The long-budget teacher develops a richer refinement trajectory, whereas the distilled student learns a more direct trajectory toward the terminal prediction under a limited inference budget.
5.5 Ablation Study
We conduct ablation studies on two key design choices of LoopGR, namely the context updater and the training objective.
For the updater, we replace the default GRU with three sequence modeling methods, including token mixing, linear attention, vanilla attention and an Identity variant that leaves the context representations unchanged. Furthermore, we compare per-step supervision, gated exit, Intra-Loop Self-Distillation (Goyal et al., 2026, ILSD;) and Recurrent Trajectory Self-Distillation (RTSD). At inference, the other alternative training objectives use the full budget and RTSD distills LoopGR into a student operating at half of the teacher’s budget.
Table 3 shows that the Mixing baseline achieves the best Recall@5, Recall@10 and NDCG@10 on Sports. In contrast, replacing the updater with Identity consistently degrades performance, with an average drop of about 8%8\% relative to the learnable updater variants. This confirms that the gain primarily comes from dynamically updating the conditioning context rather than from a particular sequence operator, making the updater design largely architecture-agnostic.
Averaged over the eight reported metrics, per-step supervision, gated exit and ILSD fall 9.7%9.7\%, 13.2%13.2\% and 9.4%9.4\% below the full-budget LoopGR, respectively. RTSD reduces this gap to only 3.2%3.2\%. We suggest that direct supervision at intermediate cycles can induce representation stagnation. It causes subsequent updates to diminish before the full recurrent budget is exploited. RTSD instead separates trajectory learning from compression and better preserves performance under a reduced budget.

6 Conclusion
In this paper, we introduce LoopGR, a parameter-efficient framework for generative recommendation that decouples computational depth from parameter growth through hierarchical recurrent computation.
By recurrently reusing a decoder and a context updater, LoopGR increases effective depth while dynamically refining the historical context during SID generation. We further develop recurrent trajectory self-distillation to better balance recommendation performance and inference efficiency under hard recurrent budgets.
Extensive experiments show that LoopGR consistently outperforms strong baselines and achieves better performance than representative Encoder-Decoder architectures with up to 52%52\% fewer parameters. These results demonstrate the potential of recurrent depth as a complementary scaling dimension beyond model size for generative recommendation.

A.2 Efficiency under Compressed Recurrent Trajectories
We further evaluate whether RTSD can preserve recommendation quality when the recurrent trajectory is compressed to fewer cycles. Reducing the teacher from 16 cycles to 8 and 4 cycles decreases computation from 17.408 GFLOPs to 8.415 and 3.918 GFLOPs, respectively. The corresponding inference latency drops from 211.08 ms to 104.01 ms and 49.82 ms under batch size 1, providing approximately 2.0×\times and 4.2×\times speedups. Despite the substantially shorter trajectories, both students retain comparable recommendation accuracy. Notably, the 4-cycle student surpasses the 16-cycle teacher on all four metrics for Sports and remains competitive on Beauty, while the 8-cycle student achieves the best Recall@10 and NDCG@10 on Beauty. These results show that RTSD can compress a long recurrent trajectory into substantially fewer cycles without proportionally sacrificing predictive quality, enabling a more favorable trade-off between recurrent depth and inference efficiency.

A.4 Implementation Details of the Context Updater
As discussed in the main text, the context updater UPD\operatorname{UPD} is model-agnostic, allowing different architectures to be incorporated into the same recurrent refinement framework. Here, we categorize the updaters into token-level and item-level variants according to their modeling granularity. Token-level updaters operate directly on individual SID token representations. Item-level updaters group the HH SID tokens of each historical item and refine the resulting item representations. Each historical item is represented by HH SID tokens. We index the context representations by item and hierarchy, and the representation of the hh-th SID token of the jj-th historical item is denoted as 𝐦j,h∈ℝd\mathbf{m}_{j,h}\in\mathbb{R}^{d}, where j=1,…,nj=1,\dots,n and h=1,…,Hh=1,\dots,H. For brevity, we omit the cycle indices.
Token-level Updaters.
Token-level updaters refine the context directly at the granularity of SID tokens. As a representative example, linear attention (Katharopoulos et al., 2020) enables each token to aggregate information from the entire history through a kernel-based attention mechanism. The prediction-aware query 𝐪\mathbf{q} is injected only into the attention query branch, while keys and values are derived from the conditioned context. Token-level updaters can also be instantiated as an MLP or an identity function, applied independently to each query-conditioned SID token representation. The MLP transforms each token through a feed-forward network, whereas the identity function leaves its input unchanged.
Item-level Updaters.
Item-level updaters treat the HH SID tokens of each item as a group rather than independent modeling units. They first organize token representations into item-level inputs. After refinement, they map the resulting updates back to the SID sequence. Specifically, the GRU updater uses mean pooling to summarize each item’s SID tokens as a vector. These vectors are projected and combined with the prediction-aware query before a bidirectional GRU (Chung et al., 2014), which processes the history in chronological and reverse chronological order. The forward and backward states are concatenated and projected to produce an item-level update 𝐮j∈ℝd\mathbf{u}_{j}\in\mathbb{R}^{d}, which is then copied to all HH SID tokens of that item. The two variants provide complementary inductive biases. The GRU updater captures bidirectional dependencies across items but compresses their internal SID structure through mean pooling, whereas the Mixing updater preserves and refines hierarchy-specific information within each item without introducing additional inter-item communication.
