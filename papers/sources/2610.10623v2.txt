Abstract
Looped Language Models (LoopLMs) offer a parameter efficient approach to scaling reasoning by reusing shared parameters across recurrent computation steps. Despite their promise, effective post-training of LoopLMs remains challenging.
Existing approaches either provide reward based supervision that is sparse or costly to extend across loops, or rely on external teachers or privileged information, leading to limited teacher availability or teacher-student context mismatch.
To address these limitations, we introduce LoopOPD, a cross-loop on-policy distillation framework that uses additional recurrent computation within a LoopLM as its own source of supervision. LoopOPD uses a frozen terminal loop policy as a compute privileged teacher for an intermediate loop student on student generated rollouts, providing dense supervision without an external teacher or privileged information.
We further propose Dynamic LoopOPD (D-LoopOPD), which continually refreshes the terminal loop teacher as the shared model parameters are updated, enabling recurrent self-improvement. We characterize how distillation updates propagate across loop depths and derive sufficient conditions under which a single update yields simultaneous local improvement at both loop depths.
Experiments on Ouro-Thinking models show that LoopOPD improves mathematical reasoning, while D-LoopOPD yields further gains through dynamic teacher updates. Despite being trained only on mathematical data, the resulting models also improve on general reasoning and code generation benchmarks, demonstrating that recurrent computation can serve as an effective source of supervision for LoopLMs. Our code and model checkpoints will be released upon acceptance.
1 Introduction
Looped Language Models (LoopLMs) have recently received growing attention as a promising approach to scaling reasoning through recurrent depth (Geiping et al., 2025). They reuse shared Transformer blocks across multiple latent computation steps before emitting each token (Zhu et al., 2025). This design increases computational depth without increasing parameter count, leading to stronger reasoning performance (Saunshi et al., 2025). However, effective post-training of LoopLMs remains challenging. Existing work applies or extends conventional post-training methods to LoopLMs, including reward based optimization and distillation, but faces limitations (Williams et al., 2026).
Specifically, prior work on Ouro, a family of pretrained LoopLMs (Zhu et al., 2025), reports limited gains from reinforcement learning with verifiable rewards (RLVR) (Guo et al., 2025) over the supervised fine-tuning (SFT) checkpoint.
Group Relative Policy Optimization (GRPO) (Shao et al., 2024) assigns reward credit only to the terminal loop, leaving intermediate latent computation without direct reward supervision. Reward Latent Thought Trajectories (RLTT) (Williams et al., 2026) alleviates this limitation by extending reward credit across all loops, but requires retaining per loop log-probabilities, causing memory usage to scale linearly with the number of loops and thereby limiting long rollout training. On-Policy Distillation (OPD) (Agarwal et al., 2024) provides dense distributional supervision but relies on an external, stronger teacher. For Ouro-2.6B-Thinking, no stronger same family LoopLM teacher is available, limiting OPD. On-Policy Self-Distillation (OPSD) instead constructs a same model teacher using privileged information (Zhao et al., 2026), but introduces teacher–student context mismatch (Kaur et al., 2026). Figure 1 (left) summarizes the three main limitations motivating our work: sparse terminal loop credit, increasing memory cost across loops, and limited availability of stronger teachers.
Effective post-training of LoopLMs therefore calls for dense supervision that directly reaches intermediate loops when no stronger external teacher is available. Because deeper loops receive more recurrent computation, the terminal loop naturally provides a stronger policy within the same model. This raises a question: Can a LoopLM leverage its own additional recurrent computation to provide such supervision to its intermediate loops?
To answer this question, we introduce LoopOPD. As illustrated in Figure 1 (right), LoopOPD uses an intermediate loop policy as the student and a frozen terminal loop policy as the compute privileged teacher. For student generated rollouts, both policies produce next token distributions on the same prefixes, and the terminal loop distribution is distilled into the intermediate loop through OPD. Unlike OPD and OPSD, the teacher’s advantage arises not from additional parameters (Li et al., 2026) or privileged information (Zhao et al., 2026), but from additional recurrent computation. LoopOPD therefore turns the model’s own recurrent computation into dense cross-loop supervision.
Intuitively, because different loops share the same parameters, training the student also updates the student model’s terminal loop policy, creating a natural feedback path from the updated terminal policy back to the student. To exploit this feedback and further strengthen cross-loop supervision, we propose Dynamic LoopOPD (D-LoopOPD), which refreshes the terminal loop teacher at each optimization step, as shown in Figure 1 (right).
The updated terminal policy then supervises the next student update, forming a closed teacher-student feedback loop for recurrent self-improvement. We further analyze cross-loop update transport and derive sufficient conditions for a single update to induce simultaneous local descent of task surrogates at both the intermediate and terminal loops. Table 1 compares the supervision signals and teacher requirements of these methods.
We evaluate LoopOPD and D-LoopOPD on Ouro-Thinking (Zhu et al., 2025) across mathematical reasoning (Zhang and Math-AI, 2026), general reasoning (Hendrycks et al., 2021), and code generation benchmarks (Liu et al., 2023). On mathematical reasoning, both methods outperform existing baselines on average, with D-LoopOPD further improving over LoopOPD. Despite training only on mathematical data, they also improve general reasoning and code generation over the vanilla models.

Existing approaches variously face sparse supervision, increasing memory cost across loops, or dependence on stronger external teachers. LoopOPD uses additional recurrent computation as dense cross-loop supervision, while D-LoopOPD dynamically refreshes the terminal loop teacher during training.
Our contributions are threefold:
• 
We introduce LoopOPD, which uses a frozen terminal loop policy as a compute privileged teacher for an intermediate loop student, providing dense on-policy supervision without an external teacher or privileged information.
• 
We propose D-LoopOPD, which refreshes the terminal loop teacher at each optimization step through shared parameter updates, forming recurrent self-improvement. We further analyze cross-loop update transport and derive sufficient conditions for local improvement of task surrogates at both the intermediate and terminal loops.
• 
Experiments on Ouro-Thinking models show improved mathematical reasoning at both model scales. On Ouro-2.6B-Thinking, D-LoopOPD raises terminal loop AIME 2024 Avg@16 from 62.08 to 71.67, with cross-loop evaluation showing improvements across all loop depths. The resulting models also improve general reasoning and code generation despite training only on mathematical data.
2 Related Work
Looped and Recurrent-Depth Language Models.
Recurrent Transformer architectures such as the Universal Transformer (Dehghani et al., 2019) explore parameter sharing across computational depth. Recent work studies this principle in language models, showing that repeated latent computation can improve reasoning and provide an additional axis for scaling test-time compute (Saunshi et al., 2025; Geiping et al., 2025). Ouro (Zhu et al., 2025) extends this line of work to pretrained LoopLMs, which recurrently apply shared Transformer blocks before token generation. Our work builds on this structure by using additional loop computation as a source of supervision.
Intermediate Supervision for Recurrent Computation.
Recent work develops training objectives for recurrent latent computation. LSRL (Ren, 2025) decodes intermediate recurrent states and scores them with an external grader to provide process supervision. RLTT (Williams et al., 2026) extends outcome reward credit from the terminal loop to intermediate loop distributions in LoopLMs. LoopRPT (Tang et al., 2026) uses an EMA teacher and noisy latent rollouts to construct stepwise reinforcement signals during pre-training, shaping intermediate representations. These methods highlight the value of directly supervising intermediate recurrent computation. Our work provides dense token level supervision to an intermediate loop using the model’s own terminal loop distribution.
On-Policy Distillation and Self-Distillation.
OPD trains a student on its own trajectories using dense teacher distributions, reducing the distribution mismatch from off-policy distillation (Agarwal et al., 2024). Recent analyses identify teacher-student compatibility and a teacher capability advantage as key factors for effective OPD (Li et al., 2026). OPSD constructs a teacher from the same model using privileged information (Zhao et al., 2026; Hübotter et al., 2026), but introduce a context mismatch that can distort supervision (Kaur et al., 2026).
In contrast, LoopOPD retains the on-policy setting and teacher-student compatibility while deriving teacher advantage from additional recurrent computation, with teacher and student conditioned on the same context. D-LoopOPD further exploits shared parameters by refreshing the terminal loop teacher as the model is updated.

3 Preliminaries
Looped Language Models.
Let xx be a prompt and y=(y1,…,ym)y=(y_{1},\ldots,y_{m}) a generated response of length mm. A LoopLM recurrently applies shared weight Transformer blocks (Vaswani et al., 2017; Zhu et al., 2025) for LL iterations before emitting each token. For the prediction of yiy_{i}, let hi(d)h_{i}^{(d)} denote the hidden state after loop dd. Let θ\theta denote the parameters of the LoopLM and gθg_{\theta} its language model head. Applying gθg_{\theta} to the loop dd hidden state defines the corresponding next token distribution
Pθ(d)(⋅∣x,y<i)=softmax(gθ(hi(d))),d=1,…,L.P_{\theta}^{(d)}(\cdot\mid x,y_{<i})=\operatorname{softmax}\!\left(g_{\theta}(h_{i}^{(d)})\right),\qquad d=1,\ldots,L.
(1)
Standard autoregressive generation uses the terminal loop distribution, inducing the sequence policy
πθ​(y∣x)=∏i=1mPθ(L)​(yi∣x,y<i).\pi_{\theta}(y\mid x)=\prod_{i=1}^{m}P_{\theta}^{(L)}(y_{i}\mid x,y_{<i}).
(2)
For d<Ld<L, we refer to Pθ(d)P_{\theta}^{(d)} as the intermediate loop distributions.
Group Relative Policy Optimization (GRPO).
For each prompt xx, GRPO samples a group of responses {y(j)}j=1G\{y^{(j)}\}_{j=1}^{G} from the old policy
πθold\pi_{\theta_{\mathrm{old}}} and evaluates them with scalar rewards r1,…,rGr_{1},\ldots,r_{G}. The group relative advantage is A^j=(rj−r¯)/σr\widehat{A}_{j}=(r_{j}-\bar{r})/\sigma_{r}. For a LoopLM, response generation uses the terminal loop distribution, so the token level importance ratio is
ρj,i​(θ)=Pθ(L)​(yi(j)∣x,y<i(j))Pθold(L)​(yi(j)∣x,y<i(j)).\rho_{j,i}(\theta)=\frac{P_{\theta}^{(L)}(y_{i}^{(j)}\mid x,y_{<i}^{(j)})}{P_{\theta_{\mathrm{old}}}^{(L)}(y_{i}^{(j)}\mid x,y_{<i}^{(j)})}.
(3)
GRPO optimizes the clipped objective
ℒGRPO​(θ)=\displaystyle\mathcal{L}_{\mathrm{GRPO}}(\theta)={}
−𝔼[1G∑j=1G1mj∑i=1mjmin(ρj,i(θ)A^j,clip(ρj,i(θ),1−ϵ,1+ϵ)A^j)]+βDKL(πθ∥πref),\displaystyle-\mathbb{E}\!\left[\frac{1}{G}\sum_{j=1}^{G}\frac{1}{m_{j}}\sum_{i=1}^{m_{j}}\min\!\left(\rho_{j,i}(\theta)\widehat{A}_{j},\operatorname{clip}(\rho_{j,i}(\theta),1-\epsilon,1+\epsilon)\widehat{A}_{j}\right)\right]+\beta D_{\mathrm{KL}}(\pi_{\theta}\|\pi_{\mathrm{ref}}),
(4)
where ϵ\epsilon is the clipping parameter, β\beta is the KL coefficient, and πref\pi_{\mathrm{ref}} is the reference policy. Thus, GRPO uses the terminal loop policy for rollouts and direct reward credit, while gradients propagate through all loops to update the shared parameters.
Reward Latent Thought Trajectories (RLTT).
RLTT extends reward credit from the terminal loop to all loops while retaining the group relative advantage (Williams et al., 2026). Its policy objective is
ℒRLTT(θ)=−𝔼[1G∑j=1G1mj∑i=1mj∑d=1LωdlogPθ(d)(yi(j)∣x,y<i(j))A^j]+βDKL(πθ∥πref),\mathcal{L}_{\mathrm{RLTT}}(\theta)=-\mathbb{E}\!\left[\frac{1}{G}\sum_{j=1}^{G}\frac{1}{m_{j}}\sum_{i=1}^{m_{j}}\sum_{d=1}^{L}\omega_{d}\log P_{\theta}^{(d)}(y_{i}^{(j)}\mid x,y_{<i}^{(j)})\widehat{A}_{j}\right]+\beta D_{\mathrm{KL}}(\pi_{\theta}\|\pi_{\mathrm{ref}}),
(5)
where ωd≥0\omega_{d}\geq 0 and ∑d=1Lωd=1\sum_{d=1}^{L}\omega_{d}=1. A limitation of RLTT is that it retain per loop log-probabilities, leading to memory usage that scales linearly with the number of loops.
On-Policy Distillation (OPD).
OPD uses token level teacher distributions rather than scalar outcome rewards (Agarwal et al., 2024). Let θ\theta and ϕ\phi denote the parameters of the student LoopLM and the frozen teacher LoopLM. For y∼πθ(⋅∣x)y\sim\pi_{\theta}(\cdot\mid x), both models are evaluated on the same prefixes ci=(x,y<i)c_{i}=(x,y_{<i}). The reverse-KL distillation objective is
ℒOPD(θ;ϕ)=𝔼[1m∑i=1mDKL(Pθ(L)(⋅∣ci)∥Pϕ(L)(⋅∣ci))].\mathcal{L}_{\mathrm{OPD}}(\theta;\phi)=\mathbb{E}\!\left[\frac{1}{m}\sum_{i=1}^{m}D_{\mathrm{KL}}\!\left(P_{\theta}^{(L)}(\cdot\mid c_{i})\,\middle\|\,P_{\phi}^{(L)}(\cdot\mid c_{i})\right)\right].
(6)
4 Method
Prior work reports limited gains from conventional reinforcement learning post-training on LoopLMs (Zhu et al., 2025; Williams et al., 2026). We explore an intrinsic source of supervision in LoopLMs: additional recurrent computation. Since a LoopLM admits a next token distribution at every loop, each loop naturally induces a corresponding autoregressive policy.
4.1 LoopOPD: Cross-Loop On-Policy Distillation
For any loop d≤Ld\leq L, we define the loop dd policy as
πθ(d)​(y∣x)=∏i=1mPθ(d)​(yi∣x,y<i).\pi_{\theta}^{(d)}(y\mid x)=\prod_{i=1}^{m}P_{\theta}^{(d)}(y_{i}\mid x,y_{<i}).
(7)
As illustrated in Figure 2 (left), LoopOPD selects an intermediate loop ℓ<L\ell<L as the student and uses the terminal loop LL policy as the compute privileged teacher.
We use ℓ=2\ell=2 and L=4L=4.
Let θ0\theta_{0} denote the initial LoopLM parameters. We initialize the trainable student with θ←θ0\theta\leftarrow\theta_{0} and the frozen teacher with θ¯0=θ0\bar{\theta}_{0}=\theta_{0}. For each prompt xx, a response is sampled from the student policy,
y∼πθ(ℓ)(⋅∣x).y\sim\pi_{\theta}^{(\ell)}(\cdot\mid x).
(8)
Both policies are evaluated on the same prefixes ci=(x,y<i)c_{i}=(x,y_{<i}), and LoopOPD distills the terminal loop distribution into the student using the reverse-KL objective in equation 6:
ℒLoopOPD(θ;θ¯0)=𝔼[1m∑i=1mDKL(Pθ(ℓ)(⋅∣ci)∥Pθ¯0(L)(⋅∣ci))].\mathcal{L}_{\mathrm{LoopOPD}}(\theta;\bar{\theta}_{0})=\mathbb{E}\!\left[\frac{1}{m}\sum_{i=1}^{m}D_{\mathrm{KL}}\!\left(P_{\theta}^{(\ell)}(\cdot\mid c_{i})\,\middle\|\,P_{\bar{\theta}_{0}}^{(L)}(\cdot\mid c_{i})\right)\right].
(9)
While LoopOPD supervises only the loop ℓ\ell student policy, the loop ℓ\ell and terminal loop policies of the trainable LoopLM share the same parameters. Updating the student therefore also changes the current terminal loop policy. Let θt\theta_{t} and θt+1\theta_{t+1} denote the parameters before and after optimization step tt. This interaction can be summarized as
πθ¯0(L)→OPDπθt+1(ℓ)→parameter sharingπθt+1(L).\pi_{\bar{\theta}_{0}}^{(L)}\xrightarrow{\text{OPD}}\pi_{\theta_{t+1}}^{(\ell)}\xrightarrow{\text{parameter sharing}}\pi_{\theta_{t+1}}^{(L)}.
(10)
4.2 Dynamic LoopOPD: Recurrent Self-Improvement
As illustrated in Figure 2 (right), D-LoopOPD leverages this shared parameter coupling by using the current terminal loop policy as the teacher at each optimization step. Its objective is
ℒD​-​LoopOPD(θ)=𝔼[1m∑i=1mDKL(Pθ(ℓ)(⋅∣ci)∥sg[Pθ(L)(⋅∣ci)])],\mathcal{L}_{\mathrm{D\text{-}LoopOPD}}(\theta)=\mathbb{E}\!\left[\frac{1}{m}\sum_{i=1}^{m}D_{\mathrm{KL}}\!\left(P_{\theta}^{(\ell)}(\cdot\mid c_{i})\,\middle\|\,\operatorname{sg}\!\left[P_{\theta}^{(L)}(\cdot\mid c_{i})\right]\right)\right],
(11)
where sg⁡[⋅]\operatorname{sg}[\cdot] denotes stop-gradient. Gradients flow only through the student distribution, while the shared parameter update modifies both the loop ℓ\ell and terminal loop policies. This interaction can be summarized as
πθt(L)→OPDπθt+1(ℓ)→parameter sharingπθt+1(L).\pi_{\theta_{t}}^{(L)}\xrightarrow{\text{OPD}}\pi_{\theta_{t+1}}^{(\ell)}\xrightarrow{\text{parameter sharing}}\pi_{\theta_{t+1}}^{(L)}.
(12)
The updated terminal loop policy then serves as the teacher for the next optimization step. Repeating this process forms a closed feedback loop between student learning and teacher evolution, which we refer to as recurrent self-improvement.
Figure 2: Overview of LoopOPD and D-LoopOPD.
LoopOPD uses a frozen terminal loop policy as a compute-privileged teacher and distills its next token distribution into an intermediate loop student on student generated rollouts. D-LoopOPD instead uses the current terminal loop policy of the same trainable LoopLM as the teacher, so each student update also changes the teacher used at the next step through shared parameters, forming recurrent self-improvement.

5 Experiments
5.1 Experimental Setup
Models.
We conduct experiments on Ouro-1.4B-Thinking and Ouro-2.6B-Thinking (Zhu et al., 2025). For comparison across model scales, we include Qwen3-1.7B, Qwen3-4B, Qwen3-8B (Yang et al., 2025), Qwen3.5-4B, and Qwen3.5-9B (Team, 2026) in thinking mode.
Baselines and Training Dataset.
For Ouro, we compare LoopOPD and D-LoopOPD against GRPO (Shao et al., 2024), RLTT (Williams et al., 2026), and OPSD (Zhao et al., 2026). We evaluate OPD (Agarwal et al., 2024) on Ouro-1.4B-Thinking, using Ouro-2.6B-Thinking as the teacher. For Qwen3, we evaluate the vanilla models and GRPO variants, while for Qwen3.5 we evaluate the vanilla models. All post-training methods are trained on DAPO-Math-17k (Yu et al., 2025).
Evaluation Benchmarks.
We evaluate mathematical reasoning on AIME 2024 (Zhang and Math-AI, 2024), AIME 2025 (Zhang and Math-AI, 2025), AIME 2026 (Zhang and Math-AI, 2026), OlympiadBench (He et al., 2024), and BeyondAIME (ByteDance-Seed, 2025). For general reasoning and code generation, we evaluate on MMLU (Hendrycks et al., 2021), MBPP and MBPP+ (Austin et al., 2021; Liu et al., 2023), and HumanEval and HumanEval+ (Chen et al., 2021; Liu et al., 2023). Detailed training and evaluation settings are provided in Appendix D.
5.2 Main Results
Mathematical Reasoning.
As shown in Table 2, LoopOPD and D-LoopOPD improve mathematical reasoning on Ouro-2.6B-Thinking. Averaging Avg@16 across AIME 2024, AIME 2025, and AIME 2026, the vanilla model and GRPO achieve 55.49 and 56.60, while LoopOPD and D-LoopOPD improve to 59.37 and 62.36. D-LoopOPD achieves the best Avg@16 on all three AIME benchmarks within the Ouro-2.6B group, improving over LoopOPD by 6.46, 1.46, and 1.05 points on AIME 2024, AIME 2025, and AIME 2026, respectively. On AIME 2024, D-LoopOPD reaches 71.67 Avg@16, surpassing vanilla Qwen3-8B at 71.25 and approaching vanilla Qwen3.5-9B at 72.08 with fewer parameters.
On OlympiadBench, D-LoopOPD also achieves the best result at 65.77, while its BeyondAIME score of 34.00 remains comparable to those of the vanilla model and GRPO.
Similar improvements are observed on Ouro-1.4B-Thinking, where LoopOPD and D-LoopOPD outperform the vanilla model, GRPO, and OPD on average across the three AIME benchmarks; LoopOPD achieves the best OlympiadBench score and D-LoopOPD the best BeyondAIME score.

5.3 Training Dynamics and Cross-Loop Performance
Training Dynamics.
Figure 3 (a) compares LoopOPD and D-LoopOPD during training. Both the rollout reward and validation performance are measured at the student loop ℓ=2\ell=2. D-LoopOPD achieves higher training reward and higher validation Avg@16 than LoopOPD. These trends support the benefit of dynamically using the current terminal loop policy as the teacher for student learning.
Figure 3: Training dynamics and cross-loop performance of Ouro-2.6B-Thinking. (a) Training reward and student loop validation Avg@16 for LoopOPD and D-LoopOPD over training. (b) Avg@16 and Pass@16 across loop depths for different methods. All evaluations use a maximum response length of 31,744 tokens. Exact values are provided in Appendix C.
Cross-Loop Performance.
Figure 3 (b) evaluates the trained models across all four loops. Both LoopOPD and D-LoopOPD improve Avg@16 over the vanilla model at every depth, with D-LoopOPD achieving the highest Avg@16 among the compared methods. At the directly supervised loop 2, D-LoopOPD raises Avg@16 from 39.16 to 47.50, a gain of 8.34 percentage points. The gains extend to loops 3 and 4, where Avg@16 increases by 5.41 and 9.59 points to 66.87 and 71.67. These results support supervising intermediate computation as an effective way to improve both intermediate and terminal policies.
Teacher and Student Entropy.
Figure 4 compares the teacher and student token distribution entropy of LoopOPD and D-LoopOPD during training.
Figure 4: Teacher and student entropy during training for Ouro-2.6B-Thinking. Left: entropy of the terminal loop teacher. Right: entropy of the student loop ℓ=2\ell=2. Both are measured on student generated rollouts.
D-LoopOPD maintains higher teacher and student entropy than LoopOPD through most of training, with the gap narrowing toward later steps. This suggests that dynamically refreshing the terminal loop teacher maintains less peaked distributions during training, which support more diverse student rollouts and broader exploration (Jin et al., 2026; Cui et al., 2025). More details are provided in Appendix C.
5.4 Ablation Study
Figure 5: Student depth ablation for D-LoopOPD on Ouro-2.6B-Thinking. AIME 2024 Avg@16 at the student and terminal loops.
We study the effect of student depth in D-LoopOPD by using loop 1, loop 2, or loop 3 as the student while keeping the terminal teacher at loop 4. As shown in Figure 5, loop 2 yields the best terminal performance, improving loop 4 Avg@16 from 62.08 to 71.67. Loop 3 already starts close to the initial terminal policy, with Avg@16 of 61.46 versus 62.08, leaving less room for distillation. In contrast, loop 1 has a much larger gap to the teacher but very low standalone accuracy. Its student Avg@16 remains at 0.63 after training, although the terminal loop improves to 68.54. Loop 2 provides a favorable balance between student capability and teacher advantage: its student Avg@16 improves from 39.16 to 47.50, while the terminal loop gains 9.59 points. These results indicate that neither a larger teacher-student gap nor a stronger student alone determines the effectiveness of cross-loop distillation. Overall, the intermediate loop ℓ=2\ell=2 yields the strongest terminal loop improvement in our setting.
6 Conclusion
We propose LoopOPD, which uses a frozen terminal loop policy to supervise an intermediate loop student through on-policy distillation, without an external teacher or privileged information. D-LoopOPD instead uses the current terminal loop policy as the teacher, allowing student updates to shape subsequent supervision through shared parameters. Our analysis characterizes this interaction and gives sufficient conditions for a single gradient update to improve task surrogates locally at both loop depths. Experiments on Ouro-Thinking models show gains in mathematical reasoning, with D-LoopOPD further improving mathematical performance over LoopOPD. Cross-loop evaluation shows that the gains extend beyond the directly supervised student to deeper loops. D-LoopOPD also improves general reasoning and code generation over the vanilla models despite using only mathematical training data. These findings support additional recurrent computation as an effective source of supervision for post-training LoopLMs.

Table 9 summarizes the evaluation protocols used throughout our experiments. For mathematical reasoning benchmarks, we use zero-shot generation with thinking enabled. For MMLU, we use the standard 5-shot multiple-choice log-likelihood evaluation, while code generation benchmarks are evaluated using EvalPlus.

For all mathematical reasoning benchmarks, each example is provided as a single user message containing the original problem followed by:

{problem}
Please reason step by step, and put your final answer within
\boxed{}.
For AIME 2024, AIME 2025, and AIME 2026, we evaluate all 30 problems from each benchmark under the same protocol. Each problem is evaluated with 16 sampled completions using temperature 1.01.0, top-pp 0.70.7, and a maximum of 31,744 generated tokens. We extract the final boxed answer and determine correctness using numerical and symbolic mathematical equivalence. We report two metrics. Avg@16 is the fraction of correct completions among the 30×16=48030\times 16=480 generated responses for each benchmark.
