# EP 实验方案：在 LoopOPD 上验证有用过程的保留

已完成[首轮受控实验](07_pilot_results_20261108.md)，包含读出／查询干预及 LoopOPD 目标与固定中间辅助的 LoRA 短训；下文仍是完整实验方案。实验组别见[矩阵](../experiments/experiment_matrix.csv)，每次执行填写[运行记录](../experiments/run_record_template.md)。

## 1. 首轮问题与范围

**以 LoopOPD 为方法起点和首要基线：它的深轮到浅轮蒸馏是否留下有价值的候选与修正未被学会？在其原目标上保留这些过程，是否优于原 LoopOPD、普通过程蒸馏或熵正则？**

“LoopOPD 未迁移有用过程”与“LoopOPD 训练损伤了原有探索”分别验证。前者比较深轮教师与训练后的浅轮学生；后者还必须证明，相对训练前的同预算学生，经过任务价值验证的探索确实减少。动机证据及主论文见[说明](06_loopopd_motivation_evidence.md)。

建议首先用一个 Ouro-1.4B-Thinking checkpoint 验证工程与小规模现象，4→2 轮；模型 revision 和预算仍待填写。若需要对照 LoopOPD 中具体 2.6B 消融，另做该规模，不能将跨规模结果混用。

先沿用冻结版 LoopOPD：学生和独立冻结教师来自同一 checkpoint；所有学生 token 固定两轮、教师四轮；保留学生 on-policy 前缀和 reverse-KL 终点目标。使用相同 tokenizer、原生模板和问题前缀；不同时加入推理路由、记忆模块、外部 steering 或新初始化。若未完全复现原训练配方，报告为受控 LoopOPD 基线，列明与原文差异。

## 2. 开始前固定配置

| 类别 | 必须记录 |
|---|---|
| 模型 | 完整 checkpoint、revision、Base/Thinking、dtype、参数更新方式 |
| 计算 | 教师/学生轮数、层栈、early-exit、prefill/decode 与缓存策略 |
| 模板 | 原生 chat template、思考模式、答案格式与停止条件 |
| 训练 | LoopOPD／D-LoopOPD 设置及与原文差异；框架 commit、目标散度、full/top-K、optimizer、学习率、seed |
| 数据 | 训练、诊断、开发、测试 ID 与哈希；问题级去重 |
| 验证 | 数学答案提取／代码执行规则、分支采样次数与长度 |
| 预算 | rollout、teacher rescore、读出、分支、搜索和训练总计算 |

问题定义、候选门槛、轮次和损失系数都不能根据测试题选择。

把训练内的标签发现／校准池，与独立的诊断确认池分开。前者可以构造监督，后者只验证现象；开发集调参，最终测试集只作最终评价。不能用同批已经挑选成功的分支同时证明方法泛化。

## 3. 阶段 D：不训练或只检查基线

### D0：各轮读出与缓存恒等检查

- 确认“一轮”的实现；固定返回位置、规范化和输出头。
- 最终轮读出的 logits 与正常前向一致。
- 对中间 state 的额外读出不得修改主计算的张量、cache 或随机数流。
- identity state 写回、无干预分支与原结果一致。
- 完整前缀重算与缓存生成在同一设置下相符，再做缓存分支。
- 教师目标不带学生梯度；教师快照真的独立冻结。

这些是后续诊断的必要实现检查。本轮已在两个输入上完成 14 项 D0 检查，记录见[工程结果](../experiments/runs/20261108_diagnostic_v2/engineering.json)；新增架构、cache 或批处理设置仍需重新验证。

### D1：建立分布变化图谱

从训练池留出诊断题。先用普通两轮学生生成前缀，再用固定四轮教师评分。记录各轮熵、相邻轮 JS/KL、候选排名变化、top-K 覆盖、长度与最终对错。

保留一个固定前缀库，用于比较原模型和后续 checkpoint；另在每个 checkpoint 新生成的轨迹上统计实际访问分布。两种统计分别报告。

分别检查三个差异：原始四轮与原始两轮反映预算影响；原始两轮与 LoopOPD 两轮反映训练影响；LoopOPD 两轮与 EP 两轮反映新增过程监督的影响。仅观察四轮比两轮更强，不能归因为 LoopOPD 破坏探索。E0 得到 checkpoint 后需重做 D1/D2 的对应检查。

初筛同时覆盖高变化和随机位置。不要只挑选已知发生纠错的成功样例，然后把结果推广到所有问题。

### D2：输出候选与修正的配对干预

在相同学生状态上，对候选 token／教师不同轮读出／修正子集采用统一学生续写，使用相同随机数安排、采样温度、预算与 verifier。记录每个分支逐题结果，不只记录平均分。

先做少量问题估计方差，再确定确认集与样本数；不要预填结果。比较完整修正、去掉某修正、联合子集、随机／同尺度分布扰动。必要时检查多个位置联合干预。

**这阶段只回答输出建议是否有用。**若要讨论真实内部计算，追加 D3。

### D3：内部状态贡献诊断（声称内部计算必要时必做）

优先用图行走、两跳检索或有限状态机建立可验证步骤。再在实际模型中使用同轮 donor、无关 donor、同范数随机方向和恒等写回控制。

保持后续轮数、cache、状态坐标与尺度的解释清楚。跳过一轮的下降可能只来自计算量减少；跨轮状态移植失败也可能来自分布外输入。先证明干预可信，再解释“必要计算”。

参考 Cross-Loop Query Handoff §4–6，先在目标 checkpoint 上建立原生循环的收益，再保持计算轮数不变，冻结回答位置 query 的跨轮更新，配对无关位置冻结、同题后轮 query 移植与打乱 donor。完整记录每层／head 的干预范围、额外 donor 前向成本，以及候选排序和真实生成是否一致。该论文在 Ouro-1.4B 上的排序修复未转成生成修复，不能替当前 Thinking 模型预填结果。

在原始模型与 LoopOPD checkpoint 上分别重复协议，判断任务相关更新的功能是否变化。外来状态的跨 checkpoint 移植另作补充，并检查表示不兼容；它不能单独证明训练损伤。若 D3 只显示状态有用、D2 未显示候选保留价值，当前证据仅支持内部计算，不足以支持多候选探索解释。

## 4. 阶段 E：最小训练对照

| ID | 方法 | 必须区分的解释 |
|---|---|---|
| E0 | LoopOPD：冻结 T4→S2，学生前缀，reverse KL | EP 的基础方法；同初始化、数据和预算的首要对照 |
| E1 | E0 + 固定 T2→S1 及其过程项 | 固定比例轨迹蒸馏是否已足够 |
| E2 | E0 + 固定 T3→S1，同 E1 结构 | 中间点位是否真的影响学习 |
| E3 | E0 + 有用位置的候选保留，μ=0 | EP 保留项的单独价值 |
| E4 | E3 + 关键修正监督 | 过程项是否提供额外收益 |
| E5 | 同 E4，但随机选择位置／匹配密度 | 是否只是增加辅助损失或正则化 |
| E6 | 终点蒸馏 + Entropy-Aware OPD 的可比适配 | 是否主要是散度与输出多样性作用 |
| E7 | 同 E4，使用等密度、不用任务价值的选择 | 任务价值选择是否优于 KL／熵／teachability |
| E8 | 终点蒸馏 + 同批验证奖励的普通任务训练 | EP 收益是否仅来自额外 verifier 信息 |
| E9 | 终点蒸馏 + 匹配位置和规模的熵辅助 | 是否只需一般熵正则，而无需过程保留 |

E3 与 E4 隔离修正项的增益；E4 与 E5 保持相同损失构件，仅改变门控。E1–E2 统一系数搜索预算。所有组继承 E0 的 LoopOPD 采样与终点目标；辅助系数全部为零时回到 E0。探索门控和候选产生过程只使用训练数据；开发集用于超参数与阶段决策。

E5 的随机位置池应尽量匹配长度、变化强度和候选数，以免高价值组只是更难或更多算力。记录辅助 loss 覆盖与梯度尺度。

第一轮实施 E0、E1、E2 后再投入 E3–E9。E6 可先使用同样的单一散度混合配方建立对照，不根据测试表现单独偏置某一组。若 EP 标签依赖 verifier，E8 是归因必需对照，不能沿用 LoopOPD“无需任务奖励”的条件描述 EP。

## 5. 训练目标与采样来源的边界

所有训练前缀由当前 S2 策略生成，属于部署的两轮学生访问分布。中间 S1 没有独立生成这些动作。

因此 S1 辅助先用显式、可比较事件上的分布损失；不能把 S2 采样的 token 直接当成来自 S1 的样本，套一个未校正的 sampled reverse-KL 更新。S2 终点目标与所有对照保持一致。

候选集包含各轮教师及学生的重要候选，报告集合构造、覆盖质量、OTHER 聚合与截断。只用学生 top-K 可能遗漏教师真正希望增加的候选。对数增量需使用稳定有限概率与明确的裁剪，不把稀有 token 的大比值当成重要性真值。

聚合事件分布的保留损失与全词表终点目标不同，需单独记录。teacher、选择结果和门控在正式更新时停止梯度。

首个可控版本可以仅在少量当前训练前缀上做预算受限的在线分支，产生 g 和候选标签，再正式更新；其余位置不加辅助。旧前缀上的静态标签不能无说明地当成新学生前缀的精确标签。若改用校准集训练的便宜选择器，需记录其预测误差、覆盖与刷新规则，且与真实分支标签的上界分开报告。

## 7. Ouro 与 Huginn 的实现差异

Ouro 要固定完整层栈的循环边界、每轮规范化与 early-exit；不能把第一物理层当成第一轮。Base 和 Thinking 单列。

Huginn 中间 core state 应复制后通过原有 coda/head 读出，不能默认直接套 head 就是可用策略。其主模型平均约 32 次 recurrence 训练，优先在正常工作范围内减半；4→2 仅作极低预算诊断。

Huginn 还需配对随机初态、记录不同轮数的历史 cache。一次深轮运行的中间读出，与所有历史 token 都只运行 r 轮的独立策略可能不同。teacher rescore 和学生实际生成各自的语义要写清。

## 8. 评测与统计

**主指标：**固定两轮普通学生的任务正确率；至少多 seed。Avg@K、Pass@K 和 greedy 分开，不能只用 30 道 AIME 作为唯一证据。

**探索证据：**高价值候选的保留、关键修正学会程度、干预后还能挽回多少错误，以及相同采样数和总 FLOPs 下的解法成功覆盖。熵本身不是成功指标。

**排除退化：**长度、截断、重复、答案格式、语言流畅度；参数共享后的四轮能力与一般能力。

**成本：**学生生成、教师评分、多轮 output head／coda、分支续写、选择器搜索、临时更新、正式训练和部署延迟。相同更新数不等于相同总计算。

按问题分组做配对区间或 bootstrap，不能把相关 token 或同题分支当独立样本。固定前缀指标变好不等于自由生成表现变好。

## 9. 阶段决策

- 无法稳定读出或分支恒等失败：先修实现，不解释机制。
- 未发现有价值候选／修正受损：暂不投入 EP 训练。
- 只有熵基线有效：收窄为散度／多样性问题。
- 普通过程项和 EP 同样有效：收窄为过程蒸馏收益。
- 随机门控同样有效：没有建立有用性选择的作用。
- 固定 T3 与动态映射相当：不保留复杂动态选择。
- 当前输出空间信号无效、内部准备态有贡献：重新研究监督对象，不强行维持候选保留解释。
