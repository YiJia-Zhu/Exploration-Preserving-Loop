# 从 LoopOPD 到 EP：中间循环为什么值得保留

更新：2026-11-08。本文核对固定版本论文的正文与 PDF，下文数字均为原作者报告。另已完成[本地首轮实验](07_pilot_results_20261108.md)，其结果与文献证据分开记录。

**研究定位：EP 的 idea 直接来源于 LoopOPD。我们继承它的跨轮 on-policy 蒸馏，研究深轮最终预测之外，哪些有任务价值的中间候选与修正还值得教给浅轮学生。**

最适合作为主要动机证据的论文是 **Cross-Loop Query Handoff: How Later Loops Redirect Two-Hop Retrieval in the Ouro Looped Language Models**，arXiv:2610.34639v1（[官方版本](https://arxiv.org/abs/2610.34639v1)，[本地 PDF](../ref/2610.34639v1_query_handoff.pdf)）。它提供 Ouro 上的干预证据，支持部分跨轮更新有计算价值。它没有训练或评测 LoopOPD，也没有证明这些更新就是多候选探索。完整研究动机需要把下面三个问题接起来。

## 1. LoopOPD 可能遗漏什么

### 1.1 原方法已经做了什么

[LoopOPD v2](https://arxiv.org/abs/2610.10623v2) §4.1–4.2、Eq. (9)/(11)（[PDF 第 4–5 页](../papers/2610.10623v2_loopopd.pdf#page=4)）的设置是：

- 冻结版 LoopOPD：从同一 checkpoint 初始化学生和独立教师。两轮学生生成前缀 `c_t`，四轮教师在这些前缀上给出分布。
- 对齐 `p_S^2(·|c_t)` 与 `p_T^4(·|c_t)`，使用 `KL(p_S^2 || p_T^4)`，即 reverse KL。
- D-LoopOPD：教师改为当前共享模型的四轮分布，并停止教师侧梯度；每次更新后教师随共享参数变化。

因此，教师最终预测中的纠错结果已经进入监督。EP 要研究的是：有限预算学生能否学会产生这种结果的有用过程，以及保留中间监督是否能帮助泛化。

### 1.2 终点约束与过程约束不同

对同一个前缀，教师可能经过 `p_T^1 → p_T^2 → p_T^3 → p_T^4`。LoopOPD 直接要求学生的两轮出口接近 `p_T^4`，并未指定学生第一轮应该保留哪些候选、两轮之间应该完成哪次修正。

这留下一个合理的失败可能：学生在常见训练前缀上学会较早给出教师终点倾向，但遇到需要比较、重查证据或修正初始判断的新问题时，可用的内部过程不足。这里的“可能”来自监督目标未约束过程，以及现实中的计算和优化限制；它本身不构成损伤证据。

两个边界必须保留：终点损失仍通过循环计算反向传播；LoopOPD 没有显式要求所有中间分布相同。如果学生在所有可达前缀上精确匹配教师最终条件分布，自回归分解保证其输出序列分布也相同。EP 的理由应落在有限资源下的学习效果上。

### 1.3 reverse KL 为什么值得检查候选覆盖

在一个固定前缀上，令 `p=softmax(z)` 为学生分布，`q` 为停止梯度、各项为正的教师分布。显式全词表目标满足：

`∂ KL(p||q) / ∂z_v = p_v [log(p_v/q_v) − KL(p||q)]`。

当某候选的 `p_v` 很小时，它对应的直接 logit 梯度可能很弱；固定 `q_v>0` 时，`p_v→0` 的极限为零。相比之下，forward KL 的对应梯度为 `p_v−q_v`。这解释了一个训练风险：已被学生压到很低概率、但教师仍认为有价值的候选，可能较难恢复。学生自己生成前缀，还会使与低概率选择相关的后续前缀较少被访问。

上述是固定前缀的局部推导，未包含共享参数、前缀采样变化、裁剪或动态教师的全部影响。reverse KL 在不受约束且能精确优化时的最优解仍是 `p=q`；不能据此断言它必然降熵或让循环轨迹变平。

[Entropy-Aware OPD v3](https://arxiv.org/abs/2603.07079v3) 提供相关实证：§3.1（[PDF 第 3 页](../papers/2603.07079v3_entropy_aware_opd.pdf#page=3)）报告，在 AIME24/25 上，Qwen3-8B 教师生成中熵 ≥1.0 的位置占 18.5%，OPD 后 Qwen3-1.7B-Base 学生为 6.8%。作者随后在高教师熵位置补充 forward KL，并报告多样性及 Pass@8 改善。

这些数据支持“OPD 值得检查候选覆盖”的动机，但比较涉及不同容量模型及各自生成的轨迹，不能单凭比例把全部差异归因于 reverse KL。它研究输出序列上的不确定性，未测 Ouro 的循环内变化。把这项风险迁移到 LoopOPD，是 EP 待检验的假设。

## 2. 主要证据论文：某些循环更新确实有任务作用

### 2.1 为什么选择 Cross-Loop Query Handoff

它直接研究 Ouro-1.4B 和 Ouro-2.6B，与 LoopOPD 使用同一模型家族，并通过冻结和移植内部查询检验计算作用。LoopOPD 使用 Ouro-Thinking；不能把模型家族相同当成 checkpoint、模板和任务完全一致。

论文的合成任务很直观：给出“Bob 有 D 盒”“D 盒里是蓝色”等事实，再问“Bob 的盒子里是什么颜色？”需要先找到 Bob 对应的盒子，再用盒子检索颜色。attention query 可以理解为模型此刻用于查找信息的查询向量。

后续循环可能把“围绕 Bob 查找”更新成“根据已确定的 D 盒查颜色”。正确颜色的 token 概率随之改变，是完成组合检索的一种外部表现；同样大小的概率变化也可能来自无关噪声，需要干预区分。

### 2.2 作者怎样区分多算几轮与特定更新的作用

| 实验 | 作者报告 | 支持的结论 |
|---|---|---|
| 普通多轮计算，400 个合成场景／模型 | 两跳准确率从第一轮到第三轮，1.4B 为 58.3%→93.8%，2.6B 为 65.3%→99.5%；单跳已接近满分 | 循环收益主要出现在组合检索 |
| 把同题第三轮 query 移入第一轮 | 在“第一轮错、第三轮对”的目标子集中，1.4B 修复 89.8%（n=245），2.6B 修复 96.9%（n=223） | 后轮查询集合包含可转移的任务信息 |
| 换成其他题的第三轮 query | 同一目标集合的修复率仅 23.7%／20.6% | 收益依赖查询内容与题目匹配 |
| 保持后续循环运行，把回答位置 query 固定为第一轮值 | 到第三轮的原始两跳增益全部消失；扣除单跳损伤后的组合特异损伤为 27.5／36.0 个百分点 | 这些条件下，查询更新对保留循环增益有因果作用 |
| 在无关位置做相同规模冻结 | 基本保留原有循环增益 | 损伤难以仅由修改位置数量解释 |

定位：§3；§4、Table 2（[PDF 第 5 页](../ref/2610.34639v1_query_handoff.pdf#page=5)）；§6、Table 5（[PDF 第 7 页](../ref/2610.34639v1_query_handoff.pdf#page=7)）。冻结实验的循环次数保持不变，因此提供了比“少算一轮后下降”更具体的过程证据。

这里移植的是回答位置在**每层、每个 head** 的后轮 query 集合，非单个向量。donor 来自额外深轮前向，修复率是诊断结果，不能作为免费的一轮部署加速结果。它只针对早错晚对的子集，也没有测出对所有原本答对题的净影响。

### 2.3 为什么它支持中间更新，尚不足以证明“必要探索”

论文 §5 的交叉置换进一步支持查询具有中间桥接实体的检索作用；不过位置因素仍然存在。在该干预协议下，合理结论是：部分循环更新承担了有任务后果的计算，完全冻结它们会损害求解。

论文没有逐轮删除每个更新，也没有证明原生计算路径是唯一可行路径。学生仍可能在两轮内学会等价计算。它没有干预中间 token 分布来证明某个候选必须保留，更没有展示多个解法候选并行探索或 LoopOPD 训练后损失这种机制。

结果也有明确边界：1.4B 的合成任务修复主要体现为四候选排序，未转化为第一轮生成颜色答案；2.6B 的 greedy 生成修复另有支持。自然问答上，2.6B 的全层移植复验为 31.8% 对随机 donor 的 23.6%，差值 8.2 个百分点，明显小于合成结果；1.4B 未显示可靠修复。自然任务的交叉置换也未建立相同桥接机制。见 §4、§7、Table 6（[PDF 第 8 页](../ref/2610.34639v1_query_handoff.pdf#page=8)）。

**用于 EP 的准确表述：已有 Ouro 干预研究表明，部分跨轮更新承担有任务价值的组合计算；EP 将检验 LoopOPD 是否充分迁移这些功能，以及中间候选监督是否是有效的保留方式。**

## 3. 答案已经可读出，为什么中间状态还要继续更新

补充证据是 [Learning to Compute Is Not Learning to Retain or Reuse in Looped Transformers](https://arxiv.org/abs/2610.19768v1)，§5、Figure 4（[PDF 第 8 页](../papers/2610.19768v1_compute_retain_reuse.pdf#page=8)）。

作者用能精确验证每一步结果的 Mealy-machine 执行任务，比较两种操作：把已正确读出的答案存到模型外；把承载该答案的隐藏状态固定住，阻止它继续更新。前者保持答案正确，后者会损害后续计算。

在 sampled-prefix 设置中，答案首次可读出时就冻结相应状态，最终位置准确率从 100% 降到 4.1%；延迟两轮再冻结恢复到 99.8%。matched random exit 设置需要延迟四轮才能达到相同水平。这里的“两到四轮”是该受控任务的结果，不能套作 Ouro 的循环数。

这说明：**当前 token 已经能读对，与承载它的状态已经适合供后续计算使用，是两个条件。**后续更新可能在整理检索接口、顺序信息或其他准备性表征，即使当前答案没有改变。这为“某些看似多余的中间计算仍有价值”提供直接证据，也提醒 EP：只观察 token 分布可能漏掉真正重要的状态功能。

该论文没有确立唯一微观机制，亦未在 LoopOPD、Ouro-Thinking 或 Huginn 上验证同一结论。它支持继续检查状态作用，不能直接证明分布保留损失有效。

## 4. 哪些变化才可称为有用探索

“中间循环 token”在这里包含两个对象：同一文字位置的隐藏状态 `h_t^r`，以及由它读出的下一 token 分布 `p_t^r`。循环通常在隐空间更新状态，多个读出分布不会逐一采样为真实文字。

因此，三种现象要分别判断：

| 现象 | 例子 | 当前可以怎样称呼 |
|---|---|---|
| 错误候选被正确候选替代 | 检索到 D 盒后，蓝色概率上升 | 有用修正；单凭这一点不称多候选探索 |
| 保留多个候选使后续有更多可成功的路线 | 两种数学分解方向都能在配对续写中求解，过早删除其中一种降低成功覆盖 | 有用候选探索，需实际干预和多次续写证据 |
| 当前预测几乎不变，状态继续整理信息 | 答案已可读出，后续位置仍依赖它再更新 | 准备性计算，分布监督未必能捕捉 |

教师中间出现、终点消失的候选并不自动值得保留。如果学生能以更少计算得到相同结果，这种删除就是有效压缩。EP 只保留能帮助后续求解、并能通过实验识别的部分。

有用探索应满足“保留不同候选有助于后续求解”，不以高熵、大 KL 或来回改答案作定义。只有在指定模型、任务和干预下，删除相关过程导致下降且恢复它能挽回，才使用有条件的“必要”。这不意味着每一轮、每个 token 的每次变化都必须保留。

## 5. 从现有证据到 EP，还缺哪一步

| 命题 | 证据状态 | 我们需要做什么 |
|---|---|---|
| LoopOPD 对齐浅轮与深轮终点，未显式约束中间轨迹 | 原方法 Eq. (9)/(11) 直接支持 | 保留该训练框架作为 E0 |
| OPD 的候选覆盖有时收缩 | EOPD 的普通 Transformer 实验提供动机 | 在同一 Ouro checkpoint 和前缀上确认，并分离散度与预算影响 |
| 部分跨轮更新对任务有因果作用 | Query Handoff 在 Ouro 的限定任务上支持；Compute/Retain/Reuse 提供受控状态证据 | 在目标 Thinking checkpoint 上验证，不能直接搬用百分比 |
| LoopOPD 训练使有用探索减少 | **尚无本项目证据；上述论文均未证明** | 比较原始两轮与 LoopOPD 两轮的候选／干预价值变化 |
| LoopOPD 未充分迁移深轮有用过程 | **待验证的较弱命题** | 比较原始四轮、原始两轮与 LoopOPD 两轮，定位剩余差距 |
| 保留中间候选能解决这个差距 | **EP 方法假设** | LoopOPD + 辅助训练需超过原 LoopOPD、普通过程、熵与随机对照 |

最小验证链是：建立原 LoopOPD 基线 → 找到相同前缀上的有价值候选／状态过程 → 对比训练前后是否损失或未迁移 → 配对删除与恢复 → 检验学生学习该过程后在新题上的收益。原始四轮比两轮强，只能证明预算差异，不能单独证明 LoopOPD 破坏了探索。

如果要主张真实内部更新有必要，必须加入状态或 query 干预；只在输出分布上替换 token 的实验仅支持输出建议的价值。若收益全由一般熵正则解释，就收窄为候选覆盖改进；若只修复一个关键候选，就收窄为关键修正学习。

## 6. 可直接用于 idea 的动机段落

> 我们以 LoopOPD 为基础，研究跨轮蒸馏如何保留对推理有价值的中间过程。LoopOPD 利用深轮最终分布监督浅轮学生，能够把额外循环计算转化为学习信号，但其目标未显式规定中间候选和预测修正如何迁移。已有 Ouro 干预研究表明，部分跨轮查询更新承担两跳组合检索；受控循环任务也发现，答案可读出后，状态仍可能需要继续更新才能支持后续计算。这提示我们：减少循环时，应检查有任务作用的过程是否被充分学会。我们进一步提出，某些候选分布变化可能保留了后续求解需要的探索空间，并在 LoopOPD 原目标上增加按任务价值选择的候选保留与修正监督。该假设通过训练前后比较、配对干预及等预算训练对照验证。

方法写作保持为 `L_EP = L_LoopOPD + λ L_preserve + μ L_revision`。`λ=μ=0` 回到原 LoopOPD；动态教师扩展另与原 D-LoopOPD 成对比较。具体定义见 [Idea](01_idea.md)，执行顺序见[实验方案](02_experiment_plan.md)。
