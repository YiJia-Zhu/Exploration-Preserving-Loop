# EP 的相关工作与主要区别

核心论文见[阅读笔记](03_paper_notes.md)，其他论文的固定版本与 PDF 见[参考入口](../ref/README.md)。区别描述不代表 EP 已更有效或已确认新颖。

**EP 的直接来源和基础方法是 LoopOPD。**继承关系为：深轮指导浅轮、学生生成前缀、原有 reverse-KL 终点目标；新增部分是按任务价值选择的中间候选保留与修正监督。D-LoopOPD 扩展沿用其动态教师，另设成对对照。OPTD、LoopGR 等用于界定新增部分与已有方法的关系。

## 1. 与主问题最近的工作

| 工作 | 它解决什么 | 已有方案 | EP 要补足什么 |
|---|---|---|---|
| LoopOPD / D-LoopOPD（方法来源） | 原生循环模型缺少便宜密集的后训练监督 | 深轮终点分布教浅轮；动态版刷新教师 | 在原方法上验证有用过程未迁移或受损，并检验新增辅助的价值 |
| OPTD：层间预测变化 | 终点 OPD 未直接传递内部预测修正 | 最终分布 + anchor layers 间增量 | 选择性保留探索是否超出统一过程监督 |
| LoopGR | 用更少循环保留推荐预测能力 | 固定比例预测轨迹 + 变化方向 | 任务价值、准备性阶段与固定对齐失配的证据 |
| 扩散语言 OPTD | 多步合并可能破坏中间依赖 | 按 outcome consistency 选择最大可合并候选 | 原生 latent depth 的候选／状态依赖与学生后续收益 |
| Entropy-Aware OPD | 高熵教师下的多样性与不稳定信号 | 按教师熵混合 reverse/forward KL | 证明 EP 不只是输出熵正则 |

两篇 OPTD 的模型、动作和目标不同：一篇是普通 Transformer 的深度预测变化，另一篇是扩散语言模型的并行 token 释放。不能混用名字与结论。

## 2. 选择哪些指导值得学

| 工作 | 原问题与方法 | 与 EP 的主要区别 |
|---|---|---|
| AOPD | 按采用教师动作后由学生继续的任务 advantage 加权 | 原来主要选择 token 指导；EP 还研究候选演化与计算压缩，但收益加权已有覆盖 |
| RAD | 临时蒸馏一步，按更新后的任务奖励调整权重 | 若 EP 用 meta-score 选监督，必须与固定映射 + RAD 比较 |
| Demystifying OPD | 用单次／重复 token flip 分离教师可用优势与学生学会多少 | 是 EP 输出干预诊断的重要原型，不能将该协议视为新方法 |
| TA-OPD | 区分可学分歧与落在学生支持集外的失配 | 可学性不等于最终任务价值；EP 选择器至少要比较该基线 |
| TIP | 按学生熵与师生分歧选择重要位置 | 是位置选择；不能仅加入该掩码就称有独立循环机制 |
| RouteOPD | 标量 credit 未指定概率从哪里移向哪里 | 已做候选间概率传输；EP 的修正保留需说明额外的循环时间和功能结构 |

“采用建议有用”“学习建议有用”“与学生支持集相容”是三种标准。EP 不能在文档或实验中把三者统称为同一个价值标签。

## 3. 动态匹配并非空白

BERT-EMD 用 EMD 做多对多层映射；ALP-KD 用 attention 融合教师层。它们已允许学生浅层接受较深教师层的信息。

RAIL-KD 表明随机中间层监督也可能有收益；Revisiting Intermediate-Layer Matching 进一步发现部分设置中许多映射策略差别不大。因此 EP 需要最佳固定映射、随机映射和相似度／attention 映射，而不只是与“没有中间监督”比较。

若 EP 后续只实现 T2/T3 的动态选择，仍然接近自动层匹配。独立价值取决于与任务后果相关的过程选择，以及在循环模型中的可重复失败与收益。

## 4. 循环内部功能的机制近邻

| 工作 | 证据 | 与 EP 的关系与限制 |
|---|---|---|
| Compute/Retain/Reuse | 合成任务分离算出、保持与重用 | 给出准备性计算的诊断原型；尚未验证 Ouro/Huginn 同样成立 |
| Shared Weights, Selected Computations | 隐藏状态控制冻结共享块执行不同已学操作 | 支持按功能而非只按轮号解释；不保证任意功能可压进一轮 |
| Cross-Loop Query Handoff（主要动机证据） | Ouro 上冻结查询更新会破坏两跳增益，后轮 query 移植可修复部分错误 | 支持限定任务下的更新价值；未测 LoopOPD 损伤或多候选探索，详见[证据说明](06_loopopd_motivation_evidence.md) |
| Jacobian Lens | Ouro/Huginn 读写和传递窗口不同 | 提醒过早修改可能被恢复，跨轮坐标与持续范围要校验 |
| Huginn 原论文 | prelude/core/coda、随机初态与不同 recurrence | 确定预算和中间读出的实现；不把 Huginn 第三轮与 Ouro 第三轮等同 |

## 5. 与计算分配方法的区别

LatentHarness 选择 Think、Recall、Exit，并对同状态的单步反事实动作做 CPD。其单步增益结合 trajectory advantage 和成本；未对每个动作都完整续写求最终成功率。

FlexLoop 保留深层任务目标并逐级蒸馏浅层，再按一致性停止，主要验证来自控制策略。

EP 第一版固定学生推理轮数，选择训练时保留什么过程。这有助于隔离监督内容和部署计算分配。若以后改成在线选择继续／停止，就必须与这类方法直接比较，并计入缓存和路由成本。

## 6. 当前方案的位置

EP 目前是基于 LoopOPD 的可检验改进方向：检查其低预算学生是否未充分保留有用过程，以任务后果选择候选保留和修正监督。其损失与评价构件均有已有方法基础。

要超出直接组合，需要证明：现有终点、统一过程、熵与动态匹配方法留下了具体失败；EP 的选择机制针对这一失败；效果不能由额外数据、分支、计算或普通正则化解释。
