# LoopOPD 改进的动机与证据边界

更新：2026-11-13。当前方案是[原生退出与 JS 阶段蒸馏](loop_distillation_research_proposal_zh.md)，旧候选保留／关键增量 loss 不再是主实现。

## 1. 从原 LoopOPD 出发

[LoopOPD v2](https://arxiv.org/abs/2610.10623v2) Eq.9 让浅轮学生在自身前缀上匹配冻结深轮终点；Eq.11 改为当前共享模型的停止梯度深轮目标。两者都已有密集的 token 分布监督，更新梯度也经过循环内部。

本次要检验的缺口是：在有限浅轮预算下，单个深轮终点是否足以传递有价值的修正，以及阶段末状态是否是更易承接的学习目标。这属于优化／迁移假设，不能从“目标没有中间项”直接推出模型损伤。

若学生在所有可达前缀上精确匹配教师终点条件分布，输出序列分布也相同。因此我们不声称所有终点蒸馏必然丢失探索。

## 2. 为什么中间更新值得检查

[Cross-Loop Query Handoff](../ref/2610.34639v1_query_handoff.pdf) 在 Ouro 的限定两跳任务中，通过保持计算轮数的 query 冻结与后轮 query 移植，检验特定计算更新的作用。它支持某些跨轮变化具有任务贡献；未测试 LoopOPD 训练损伤，也没有证明每次分布转折都必须保留。

[Compute/Retain/Reuse](../papers/2610.19768v1_compute_retain_reuse.pdf) 发现，在其受控任务中，答案已可读出时的状态仍可能需要继续更新，才能供后续计算使用。这提醒我们：只检查当前答案或分布平稳，可能漏掉准备性功能。

本项目11月8日的 Thinking 模型查询干预结果见[历史实验](07_pilot_results_20261108.md)。那次实验没有使用本次原生出口＋JS 分段，不能作为新方法已有效的证据。

## 3. 为什么选择原生出口与 JS 段末

原生退出提供基模已有的监督范围 n_t；它可能减少总是监督最深终点的问题，但本身不保证该出口答对。JS 衡量前 n_t 轮内的预测转折，段末提供执行完该阶段后的真实分布，不增加融合网络。

当前实现选择最大的超阈值转折作为边界，是一个便于检查的假设。其价值需要 B/C/D 比较：B 检验终点、C 检验额外阶段、D 检验转折位置。JS 大不等于正确性高，也不等于学生可学性强。

结果筛选只可缓存样本是否被接受；当前学生前缀上的 n_t 与阶段目标要重新计算。查询冻结／恢复可另做机制解释，不把其昂贵干预作为默认训练标签。

## 4. 什么时候可以谈必要探索

至少要联系起：该阶段的更新影响任务后果；相应过程在浅轮迁移中不足；学习阶段目标后，在独立题上改善固定浅轮结果。只见 JS 大、熵高或一次候选纠正，只足以描述分布变化。

“关键跨轮探索”在当前计划中是工作假设。原生退出、段末监督或 CPU 代码核验都不能独自完成这条证明；具体反证和收窄条件见[认识与假设](04_insights.md)。
